Design check and suggestions ​

The design check that runs while you draw, fixing and ignoring findings in the problem list, suggestions while typing, and relationship name matching.

There is a short introduction in Draw tables, columns and relationships in Quick start.

Design check ​

The model is checked after every edit and problems are reported. No finding ever blocks saving or exporting.

SeverityMeaningOn the canvas
Error ●A problem that makes the DDL fail when runMark on the table header (and on the Outline item), wavy underline on the column line
Warning ▲A problem worth fixingMark on the table header (and on the Outline item), wavy underline on the column line
Info iGood to knowOnly in the problem list by default
  • Hover over a mark to read the finding.
  • Table and view items in the Outline get the same marks (the most severe finding for the table and its columns). Canvas and palette › Outline
  • View › Show design check marks turns all canvas marks on or off. Turn on View › Show info marks on canvas to draw info findings on the canvas too.
  • The Problems: … button at the right end of the category tab row counts only errors and warnings (not info or ignored findings) and hides when there is nothing to count. Click it to open the problem list.
  • Checks follow the document's target database and version (for example reserved words and name length limits). Change the target version at the left end of the status bar.
  • F8 / Shift+F8 go to the next and previous finding.

Rule IDs are used with --disable and --only of the command-line relio lint. The default severity is the value before you change it in Settings; as noted in parentheses, some rules report at a different level in certain cases.

"Use the word's physical name" appears only when exactly one word in the dictionary has the same logical name as the item with the empty physical name (it does not appear for foreign key columns), and fills in that word's physical name. For findings without a fix button, double-click the item and fix it in the properties dialog. Turn each rule on or off and change its severity in Settings › Design check.

Problem list ​

The problem list in the bottom panel (Ctrl+J, or View › Panels › Bottom panel (Problem list)) collects design check findings, repairs made when opening a file, and DDL export warnings.

  • Toggle each severity, filter with the Find target or message field, and use Group by rule to see findings per rule.
  • Click an item to go to that object on the canvas and highlight it briefly; double-click to open its properties dialog. If the object is not in the current category tab, Relio tells you to look for it in the "All" tab.
  • Use the fix button on an item (for example Create index or Match type) or Fix all: … on a rule header to fix them in one go. One undo reverts it.
  • Info findings are folded into one line per rule; click it to expand.
  • Select several rows with Ctrl or Shift and right-click for Fix all selected, Ignore here, Turn off '…' for this file, Copy list (Markdown) and Copy as CSV.
  • Right-click a node, column or line on the canvas to fix or ignore findings from Findings (n) ▸ at the bottom of the menu.

Ignoring findings ​

  • Ignore here — Hides that one finding.
  • Turn off '…' for this file — Turns that rule off for this file.
  • Ignores are recorded per file in the app settings on this PC, not in the .erm. The document is not marked as changed, and ignores are not shared with your team.
  • Use Show ignored in the problem list to see them and Stop ignoring to bring one back. Remove ignores whose target no longer exists cleans up stale ones.

Note

The command-line relio lint does not use this PC's ignores, so it gives the same result on every PC. Turn rules off in CI with --disable. Command line › relio lint

Notes where you type ​

  • The table and column properties dialogs show a line under the field for an empty physical name, a table with the same name, Korean letters, spaces, reserved words and an empty type (nothing is blocked).
  • In a new column dialog, notes for fields you have not touched wait until you type in that field or leave it once.
  • The DDL export dialog shows "This document has n errors that make the DDL fail". DDL

Suggestions while typing ​

When you type a physical or logical name in the column properties dialog, candidates come from the word dictionary and the columns of other tables.

  • The list opens above the field so it does not cover the fields below. It shows up to 8 candidates.
  • Pick with ↓ / ↑ and accept with Enter or Tab to fill in the name, type, length and logical name at once. Clicking a row also accepts it.
  • An Enter pressed without first picking with ↓ does not accept a candidate. Hovering over a row does not pick it either.
  • If you accepted the wrong one, click Undo fill.

Relationship name matching ​

  • With the 1:N relationship tool, clicking the parent table highlights candidate child tables that have columns with matching names ("n candidates with matching names are highlighted").
  • If a new relationship leaves the child with two columns of the same name, a notice bar appears. Use the existing column as the foreign key switches the original column into the foreign key in one step (its type follows the parent). Leave as is closes the bar.

Suggestions while typing, relationship name matching and canvas marks can be turned off in Settings › Design check.
