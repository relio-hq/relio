Databases ​

The database connection dialog, Import from DB, Export to DB, preparing Oracle and ODBC, and how passwords are stored.

The step-by-step version is in Import from and apply to a database in Quick start.

Supported databases ​

DatabaseHow to connect
PostgreSQL · MySQL · MariaDB · SQL Server · SQLiteThe drivers are built into the app; nothing else to install.
OraclePrepare Oracle Instant Client (see below).
Db2 · Informix · MS AccessInstall the database's ODBC driver (see below).
H2 · HSQLDBNo direct connection. Export a DDL file and run it.

For documents whose database cannot be connected to directly, Import from DB and Export to DB are dimmed.

Connection dialog ​

Import from DB and Export to DB use the same connection fields.

FieldDescription
Saved connectionsPick a saved connection to fill in the fields. Delete removes it from the list.
Server · Port · DB nameWhere to connect. Oracle also uses the Service name, and Informix the Server name (INFORMIXSERVER). For SQLite and MS Access, choose the DB file path.
User · PasswordThe login user name and password.
Remember password (Windows Credential Manager)Stores the password in the Windows Credential Manager.
Save password in the .erm (ERMaster-compatible — plain text)Stores the password inside the .erm, as ERMaster did. Relio asks you to confirm before turning it on.
ODBC driver · DSNFor Db2, Informix and MS Access. See "ODBC drivers" below.
Oracle client pathFor Oracle. Only the folder registered in Settings › DB connections is used.

Expand Advanced ▾ for:

  • Connection string — A JDBC URL, a TNS alias or connect descriptor (Oracle), an ODBC connection string (key=value;…) and so on. When filled in, it takes precedence over the server, port and DB name.
  • TLS (SSL) — Use if the server supports it · Always use · Do not use.
  • Trust server certificate (self-signed) — Turn this on to connect to a server that uses a self-signed certificate.
  • Connection timeout (s) — 1–600 seconds; 15 seconds if empty.

Buttons at the bottom:

  • Test connection — Tries to connect and reports the result (database product and version).
  • Connection name + Save to connection list — Saves the connection so you can pick it next time. Passwords are not stored in the connection list.

Import from DB ​

File › Import › From DB… goes through Connect → Schema → Objects → OK. Click Next to move on.

  1. Connect — Fill in the connection fields above.
  2. Schema — Choose the schemas to import. System schemas are unchecked by default, and Hide system schemas hides them from the list. Filter with Find schema name.
  3. Objects — Check the tables, views, sequences and triggers to import.
  4. OK — Review the number of objects to import and the options, then click Import.

Options:

  • Clear the current diagram's contents — Clears the current document and imports from the database (asks for confirmation; can be undone).
  • Use logical names as column comments — When on, the database comments on tables and columns are read as logical names. A comment shaped like "logical name : description" is split into the logical name and the description; otherwise the whole comment goes into both the logical name and the description. When off, logical names are filled from physical names (with translation dictionary translations first, if turned on) and comments go into the description. Objects with empty comments are filled the same way even when this is on.
  • Merge words — When on, words whose physical name, logical name, type, length, scale and description are all the same are merged into one in the word dictionary (also with words already in the document); when off, a separate word is created for each column.
  • Change the model DB to … — When the connected database differs from the document's database, changes the document's database.
  • If translation dictionaries are turned on (Model › Translation management…), logical names are filled from physical names.

For objects with the same name, choose Overwrite (replaces only the contents; position, color and categories stay) · Skip · Add with a new name. The whole import is undone with a single undo (Ctrl+Z).

When you connect from a new document, or save for the first time after importing, the connection details are remembered for that file too.

Export to DB ​

File › Export to DB… (also on the toolbar) creates the model directly in a database.

  1. Fill in the connection fields.
  2. On the Review and run SQL step, look over the SQL to run first. At the top you see the target database and version, the number of objects to drop, and either "Fully rolled back on failure" or "Only part may be applied on failure".
  3. If needed, turn on Also create tablespaces (needs DBA rights and server paths) and click Regenerate SQL.
  4. Click Run. Relio tells you again what will be dropped and asks you to confirm. If some schemas do not exist in the database, it asks whether to add CREATE SCHEMA statements at the beginning.
  • On databases that can roll back DDL inside a transaction, everything runs in one transaction; if a statement fails, the database is rolled back to the state before running. On other databases, the statements that succeeded stay applied, and Relio tells you which statement failed.
  • You can Cancel while it runs.
  • To apply only the changes, use migration SQL from the comparison view instead of Export to DB. Git and merging › Generating migration SQL

Warning

Export to DB can drop and recreate objects with the same name, and the data in those objects is lost. Always read the "DB objects to be dropped" list in the confirmation before running, and back up production databases first.

Preparing Oracle ​

  1. Download Oracle Instant Client (Basic or Basic Light) from the Oracle website and unzip it.
  2. Register that folder (the one with oci.dll) as the Oracle Instant Client folder in Tools › Settings › DB connections. It must be a full path; network paths cannot be used.
  3. Restart the app for a change to take effect. If no folder is registered, PATH is searched.

ODBC drivers (Db2, Informix, MS Access) ​

  1. Install the database's ODBC driver.
  2. In the ODBC driver field of the connection dialog, enter the installed driver's name (as shown in the ODBC Data Source Administrator), or choose a DSN. If you enter a DSN, its settings are used instead of the server, port and database.
  3. Set the default driver name for each database in Tools › Settings › DB connections. To use a driver file (.dll) directly, you must register it there.

How passwords are stored ​

  • Default — In the Windows Credential Manager (entries starting with relio:).
  • Not stored — Turn off Remember password and you are asked every time you connect.
  • Inside the .erm — Stored in plain text inside the file, as ERMaster did. This is turned on per file, and anyone you give the file to also gets the password.
  • See and delete stored passwords in Tools › Settings › Password. Which method each file uses is remembered per file on this PC.

Security ​

Driver files, network paths (\\server\…) and DSN files written in an .erm you received are not used, and Relio tells you they are not used for security reasons. If you trust the value, register it in Settings or enter it directly in the connection dialog.

Command line ​

Use relio db test · export · import · roundtrip to test connections, export and import without opening the app. Pass the password as the name of an environment variable with --password-env. Command line › relio db
