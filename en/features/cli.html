On this page

Command line ​

How to export, import, compare, merge, check and work with databases without a window, using the same executable (relio). It fits well in build scripts and CI.

The workflow with Git is in Work together and merge with Git in Quick start.

Getting started ​

  • To run it as plain relio, turn on "Use relio from the command line" on the last page of the installer (off by default). It adds the install folder to your own user PATH (no administrator rights needed), and uninstalling removes just that entry. It takes effect in newly opened terminals.
  • If you left it off, or use the portable version, use Copy command-line path in Help › About Relio or in the Tools › Command line & AI connection… window to copy the full path of the executable you are running, already in quotes, and paste it in place of relio.
  • To see whether it is on your PATH now, check "Use relio from the command line" (On or Off) in the Tools › Command line & AI connection… window. If it is off, run the installer again and select the third box on its last page, "Use relio from the command line". Terminals that were already open must be reopened.
  • See the options with relio --help, relio export <kind> --help, relio import --help, relio diff --help, relio merge --help, relio lint --help, relio db <command> --help and relio mcp --help.
  • Output follows the app language; change it with the RELIO_LANG environment variable (ko · en · ja · zh).

relio export ​

relio export <kind> --input <model.erm> --output <output>

  • Kinds — ddl · image · html · excel · testdata · dictionary · translation · java · dbml · mermaid · markdown · json.
  • Without options, the last export settings saved in the .erm are used.
  • The options for each kind are in the "Options by kind" table below.
  • --encoding — UTF-8 (default) · UTF-8 BOM · UTF-16LE · UTF-16BE · EUC-KR · CP949 (MS949) · Shift_JIS · GBK. An unknown name is an error (it is never silently replaced with UTF-8).
  • Standard output — --output - writes to standard output for the text kinds (ddl · dictionary · translation · dbml · mermaid · markdown · json).
  • relio export ddl prints one line to standard error when there are design check errors (problems that make the DDL fail when run).

Output path rules ​

  • An existing output file is overwritten without asking, and a missing output folder is created.
  • If the output path is the same as the input .erm, nothing is written and the command fails.
  • Without --output, the path saved in the .erm is used — but only when it points inside the folder of the .erm. An absolute path outside it, another drive, a network path or .. fails with a request to use --output (so an .erm from someone else cannot overwrite other files).
  • If the extension does not match the kind, a warning is shown and the file is written anyway.

relio merge ​

relio merge base.erm current.erm incoming.erm -o result.erm

  • The result never contains conflict markers (it is always a valid .erm). When conflicts remain, the value from the --on-conflict ours|theirs side (default ours) is used and the command ends with exit code 5.
  • --keep-numbers ours|theirs — The side whose numbers are kept.
  • --report <path|-> · --report-format markdown|json — Report of conflicts and automatic items.
  • --label-base · --label-ours · --label-theirs — Labels in the report.
  • --no-sort — Turns off sorted saving. --lang — Output language.
  • -o may be the same path as the current input. Nothing is written to the repository.

Git merge driver ​

Add one line to the repository's .gitattributes and register the driver in the Git configuration, and git merge and git rebase merge .erm files at the model level. When conflicts remain (exit code 5), Git leaves the file conflicted; open it in Relio and finish with File › Compare and merge › Resolve Git merge conflict….

# .gitattributes
*.erm text eol=lf merge=relio

git config merge.relio.name "Relio model merge"

# Windows (Git Bash) — full path of the installed relio.exe
git config merge.relio.driver '"C:/Users/<user>/AppData/Local/Relio/relio.exe" merge %O %A %B -o %A --label-base %S --label-ours %X --label-theirs %Y'

# when relio is on the PATH
git config merge.relio.driver "relio merge %O %A %B -o %A --label-base %S --label-ours %X --label-theirs %Y"
  • If you did not turn on "Use relio from the command line" when installing, relio is not on your PATH, so on Windows write the full path of relio.exe with / and wrap it in quotes (the first example above). Copy it, quotes included, with Copy command-line path in Help › About Relio, then change \ to /.
  • text eol=lf in .gitattributes keeps line endings inside commits as LF. In teams that mix ERMaster (CRLF) and Relio (LF), this stops the whole file from showing as changed because of line endings.
  • --label-base %S labels the base in the report with the common ancestor's name instead of Git's temporary file name.
  • The driver is Git configuration and does not travel with the repository. Everyone who merges, including teammates who use ERMaster, must register it on their own PC. Without it, git merge merges by line and leaves conflict markers.

Warning

If the driver is registered but Git cannot find it (wrong path — a line such as relio: command not found in the output), Git marks the file conflicted but leaves only your side, with no conflict markers. Running git add as is would drop the incoming changes. After registering, make sure that running the path from git config --get merge.relio.driver as "…/relio.exe" --version prints a version number, and that git check-attr merge -- model.erm shows merge: relio.

relio mcp ​

A local MCP server that your AI tool (Claude Code, Claude Desktop, Cursor and others) starts and uses. You do not run it yourself; you register it with your AI tool once.

claude mcp add --scope user relio -- relio mcp
claude mcp list
claude mcp remove relio --scope user
  • --scope decides in which folders Relio is connected when you start your AI tool — user (every folder, recommended), local (only this project folder) or project (with your team, by committing .mcp.json). It does not change which files the AI can see.
  • Its options are --root <folder> (repeatable), --anonymize and --read-only; run relio mcp --help for registration examples. When relio is not on your PATH, it also shows the registration line for that executable.
  • In the Tools › Command line & AI connection… window you can choose a scope and copy the lines to register and remove Relio.

Registration scopes, Claude Desktop and Cursor settings, which files the AI can see and how to use it safely are in Working with AI.

Exit codes ​

CodeMeaning
0Success (including warnings) — with diff --exit-code, no differences
1Input or option error (import: no tables found, or warnings with --strict)
2Output write failure (import: an existing .erm without --force)
3Cannot convert to this database
4Differences found (db roundtrip, diff --exit-code)
5Merge conflicts remain (merge)
6Findings at or above the --fail-on level (lint)

Using it in CI ​

  • Check — relio lint model.erm --fail-on error fails the build when there are errors.
  • Generate DDL — relio export ddl --input model.erm --output model.sql --db-version 17.
  • Review changes — relio diff --rev main model.erm --format markdown --output diff.md records what changed as a document.
  • Migration SQL — relio diff before.erm after.erm --format sql --output alter.sql.
