Working with AI ​

How to ask your own AI tool — Claude Code, Claude Desktop, Cursor and others — in plain words to read Relio models, draft new models from requirement documents, and change open models.

What it is ​

  • You do not enter an address (URL) in your AI tool. Instead, you register the program relio mcp with your AI tool once. When needed, the AI tool starts relio mcp on your PC and talks to it (a local MCP server).
  • Everything happens on your PC. Relio itself has no AI, and there is no network access, no sign-in and no Relio server. Your AI tool is what answers questions and writes text.
  • Changes from the AI go straight into the open document in the Relio window (not saved yet). One undo takes them back, and the file changes only when you save.

Getting started ​

  1. Register (once) — Before starting your AI tool, paste the line below in a terminal. If claude mcp list shows relio, you are done.

    claude mcp add --scope user relio -- relio mcp

    If relio is not on your PATH, see When relio is not on your PATH below. You can also choose and copy this line in Tools › Command line & AI connection….

  2. Start your AI tool again — Only a newly started AI tool sees the registration. For Claude Code, run claude in the folder that holds your models.

  3. Your first request, inside the AI tool — For example, type:

    Use Relio to explain the tables in shop.erm

You usually do not have to mention Relio: for requests about .erm files, tables, columns or indexes, the AI tool uses Relio's tools on its own.

What you can do ​

① Draft an ERD from requirement documents ​

Read the requirement documents in this folder, draft an ERD and open it in Relio

The AI reads the documents, creates a new .erm draft and opens it in Relio right away. It never overwrites an existing file and does not create files outside the folders the AI tool is using. If you started the AI tool in your home folder, it first asks which project folder to use. In Claude Code you can also start with the suggested prompt /mcp__relio__draft_from_requirements.

② Change an open model ​

Add audit columns to the selected table

  • Select a table in the Relio window and say "the selected table…" — the AI knows which table you mean.
  • Changes from the AI go straight into the open document. If the file is not open, Relio opens it; if Relio is not running, it starts.
  • The changed tables are briefly highlighted and a notice such as "AI changed ORDERS and 2 more [Undo] [Show changes]" appears. One Undo (or Ctrl+Z) takes you back to before the AI change. If you made other edits after it, use Edit › Undo.
  • The document is marked unsaved. If you like the result, save it yourself (Ctrl+S).
  • If the change overlaps your unsaved edits, it is not applied directly; you pick in a merge tab instead. See Review first and the merge tab below.

③ Read models and run design checks ​

Explain this model by business area

Summarize the design check results by severity

The AI reads the model summary, tables and relationships to explain them, or runs Relio's design check and sorts errors, warnings and notes by severity. It uses the same rules as the app's problem list. Read-only requests do not change any file.

Registering ​

Connection scope ​

Claude Code asks for a scope when you register. The scope decides in which folders Relio is connected when you start your AI tool (it is how Claude Code registers servers). It does not change which files the AI can see — see Files the AI can see below.

ScopeMeaningRegistration line
In every folder user (recommended)Relio is connected wherever you start your AI tool.claude mcp add --scope user relio -- relio mcp
Only in this project folder localPaste the line in a terminal opened in that project folder.claude mcp add --scope local relio -- relio mcp
With your team projectCreates .mcp.json in that folder; commit it and teammates are connected too. Each teammate must install Relio and turn on the command line (relio), and Claude Code asks for permission the first time. Because install paths differ, it always uses the relio mcp form.claude mcp add --scope project relio -- relio mcp

Choose a scope in Tools › Command line & AI connection… to copy the registration line for it.

Claude Desktop · Cursor ​

Claude Desktop and Cursor are set up in a settings file, not with a terminal command. Both use the same shape.

AI toolSettings file
Claude Desktopclaude_desktop_config.json
Cursor.cursor/mcp.json
{ "mcpServers": { "relio": { "command": "relio", "args": ["mcp", "--root", "C:\\work\\models"] } } }
  • These apps start relio mcp somewhere other than your model folder, so always give your model folder with --root.
  • Inside JSON, write each \ twice (\\). Add options one by one to args.
  • Restart the app after registering.

When relio is not on your PATH ​

If you did not turn on "Use relio from the command line" when installing, or you use the portable version, relio is not on your PATH. Then put the full path of the executable in place of relio. Copy command-line path in Help › About Relio or in the Tools › Command line & AI connection… window copies the full path of the executable you are running, already in quotes. relio mcp --help also shows the registration line for that executable when it is not on your PATH. Options ​

Put options after relio mcp. For example: claude mcp add --scope user relio -- relio mcp --root "C:\work\models" --anonymize

OptionWhat it does
--root <folder>Adds a folder the AI can see. Repeat it for more. Without it, the folder you started the AI tool in.
--anonymizeAnswers only with a model whose table, column and other names are replaced with numbers such as T1 and C1 and whose descriptions, notes and default values are empty. Types, lengths, keys, relationship structure and file names are still sent. There are no write tools.
--read-onlyRemoves the write tools (create_draft and propose_change). What the AI reads is still sent.

Files the AI can see ​

  1. .erm files open in Relio — in any folder, and whichever folder you start the AI tool in, the AI can read and change them. Only that file is allowed: not other files in its folder, and no new files next to it. Once you close it in Relio, it can no longer be used.
  2. The folder you started the AI tool in and the .erm files under it
  3. Folders added with --root

Some folders are refused. If you give one of these with --root, or start the AI tool in one, that folder is not allowed.

Refused foldersWindows
The top of a driveC:\
The top of your home folder and abovethe top of your home folder, C:\Users
System folders and everything in themthe Windows folder, Program Files, Program Files (x86), ProgramData
Network foldersUNC paths, mapped network drives

If you start the AI tool in your home folder, it still connects and sees only the files open in Relio. To use a whole folder, start it again from the project folder that contains your .erm files, or register with --root <folder>.

Removing the registration ​

Remove it for the scope you registered with. This leaves the Relio app and your files as they are.

claude mcp remove relio --scope user
claude mcp list

If you registered with local or project, remove it in that project folder with --scope local or --scope project. When claude mcp list no longer shows relio, it is removed.

What you see in the window ​

  • AI connected — Shows at the right of the status bar while an AI tool is connected. It soon goes away when the AI tool exits (even if it crashes).
  • First connection notice — The first time an AI tool connects, an "AI tool connection" window appears once. It explains that AI changes go straight into the window and the file changes only when you save, and that what the AI reads is sent to that AI service. View guide opens this section of the in-app user guide.
  • Apply notice — When the AI changes the model, the changed tables are briefly highlighted and a notice with Undo and Show changes appears. See ② Change an open model above.
  • Reloading outside changes — While an AI is connected, if an open file changes outside (including changes by programs other than the AI tool) and you have no unsaved changes, Relio reloads it without asking. It highlights the changed tables for 3 seconds and shows a line such as "AI change applied: ORDERS and 2 more" in the status bar; click it to go to the table. If you have unsaved changes, it does not reload and asks with Merge… as before. File › When you return to the window

Review first and the merge tab ​

AI changes apply right away by default, but in these cases they open in a merge tab "Merge: <file> — AI proposal" where you pick what to take and Apply:

  • When the AI change overlaps your unsaved edits
  • When cell editing, dragging or a dialog goes on for more than 10 seconds (if shorter, Relio waits until you finish and then applies)
  • When you set AI changes to Review first in Tools › Settings › General › AI tools (the default is Apply right away) — it then always opens a merge tab

In the merge tab, the base is File when the proposal was made, your side is the open document (including unsaved edits), and the other side is the AI proposal. You pick and apply items the same way as in Git and merging › Merge tab. Proposal copies are kept in mcp\proposals in the settings folder and deleted when the app starts after 7 days.

Open in AI tool ​

Tools › Open in AI tool… (also on the document tab's right-click menu) only opens a terminal in the folder of that .erm. It never runs a command for you. The "Open in AI tool" window shows these steps in order, each with a Copy button:

  1. Paste into the terminal — the registration line (first time only). It is already on your clipboard when the window opens, and follows the scope chosen in the Command line & AI connection window.
  2. Start your AI tool — for Claude Code, run claude.
  3. Your first request, inside the AI tool — for example "Use Relio to explain the tables in <file>". Another example, a draft from requirement documents, is shown too.

If the terminal cannot be opened, the window shows the folder path so you can open a terminal there yourself.

Command line & AI connection window ​

What you see in Tools › Command line & AI connection…:

  • AI connection — the connection status (AI connected or Not connected), how AI changes are applied (Apply right away or Review first — change it in Settings › General), the connection scope (In every folder, Only in this project folder, With your team), and for the chosen scope the registration line, the line to remove it and a check that it is registered (claude mcp list).
  • Command line — whether "Use relio from the command line" is on or off, the command-line path and Copy command-line path. When it is off, the window tells you how to turn it on (see When relio is not on your PATH above).

Passing a file or location ​

To tell the AI exactly which file or table you mean, copy it and paste it into your AI tool:

  • Tools › Copy current file path — the current file's path
  • Right-click a table or view on the canvas or in the outline › Copy location for AI — one line such as ORDERS table in "…\shop.erm"

With several models and no file named, the AI asks first.

Your AI tool picks these on its own. You do not need to call them yourself.

get_tableAll columns, indexes and relationships of one table

With --read-only or --anonymize, the write tools (create_draft and propose_change) are removed.

There are also four suggested prompts. They show up if your AI tool lets you pick from a prompt list; in Claude Code, run them as slash commands /mcp__relio__<name> (for example /mcp__relio__explain_model).

Suggested promptWhat it does
explain_modelExplains the model by business area — what the main tables hold and how they relate
review_ddlReviews the DDL and design and lists problems by severity
change_impactFinds the tables, relationships and foreign keys a planned change touches and suggests an order of work
draft_from_requirementsDrafts an ERD from requirement documents

Using it safely ​

Warning

  • What the AI reads (table and column names and descriptions) is sent to your AI service. You are told once, the first time it connects. For company models, hide names and descriptions with --anonymize and narrow the folders with --root (--read-only only blocks writing, not sending).
  • AI changes made through Relio go only into the open document; the file changes only when you save. Relio writes only new draft files and the mcp folder in the settings folder.
  • However, apart from Relio, your AI tool can edit .erm files directly with its own file editing features. Keep a backup of your model folder or protect it with version control such as Git.
  • The AI reads saved files. It does not see what you have not saved in the window yet (that is why overlaps open in a merge tab).
  • There is no rename tool, so when the AI renames a table or column it may apply as a delete plus an add.

Frequently asked ​

I registered it in a terminal, but Relio is not in the Claude desktop app's connector list. Registering with claude mcp add in a terminal is a Claude Code registration, so it does not show up in the desktop app's connector list. Check that it is registered with claude mcp list in a terminal.

I registered it, but the AI tool does not use Relio. Only a newly started AI tool sees the registration. Quit the AI tool and start it again. If relio is not on your PATH, register with the full path as in When relio is not on your PATH.

I started it in my home folder and the model list is empty. Your home folder is not allowed as a whole, so only files open in Relio are visible. Start it again from the project folder that holds your models, or register with --root. Files the AI can see
