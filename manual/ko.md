# Relio 사용 설명서

Relio는 ERMaster(`.erm`) 파일을 그대로 열고 저장하는 ERD·데이터베이스 모델링 도구입니다. 이 설명서는 앱 안에 들어 있어 인터넷 없이 볼 수 있습니다.

## 시작하기

- **기존 파일 열기**: 파일 › 열기(Ctrl+O), 또는 `.erm` 파일을 창에 끌어다 놓습니다. 같은 파일을 다시 열면 이미 열린 탭으로 갑니다. 여러 파일은 탭으로 열립니다.
- **새로 만들기**: 파일 › 새 다이어그램(Ctrl+N)에서 DB 종류와 대상 버전을 고릅니다(MySQL이면 MySQL·MariaDB도). 버전을 고르지 않으면 "버전 미지정"으로, 그 DB의 가장 낮은 지원 버전(예: PostgreSQL 9.4)부터 되는 문법을 기준으로 검사하고 DDL을 만듭니다 — 모르면 그대로 두세요. 처음 저장할 때 위치와 이름을 정합니다. 대상 버전은 `.erm`이 아니라 이 PC의 설정에 파일마다 기억되고, 상태 표시줄 맨 왼쪽(예: "PostgreSQL 16")을 눌러 언제든 바꿉니다.
- **샘플 열기**: 시작 화면이나 도움말 › 샘플 열기에서 PostgreSQL(온라인 서점, 테이블 19개)·MySQL(회원·권한 관리, 테이블 16개) 샘플을 고릅니다. 앱에 들어 있어 인터넷 없이 열리고, 이름 없는 새 문서(사본)로 열리므로 고쳐도 샘플은 그대로입니다. 저장하면 다른 이름으로 저장 창이 뜹니다. 문제를 알려 주실 때 샘플로 재현해 주시면 확인이 빠릅니다.
- **물리명·논리명·단어**: **물리명**은 DB에 실제로 쓰이는 이름(`EMP_NO` — DDL에 나감, 보통 영문자·숫자·`_`), **논리명**은 사람이 읽는 이름(`사원 번호` — 화면·문서·DDL 주석에 나감, 한글 가능)입니다. 보기 메뉴에서 캔버스에 어느 쪽을 보일지 고릅니다. **단어**는 단어 사전의 한 항목(물리명·논리명·형식·길이·설명 묶음)으로, 컬럼은 단어를 가리키므로 같은 단어를 쓰는 컬럼은 함께 바뀝니다. 물리명만 치면 논리명이 따라 채워지고(사전에 같은 물리명의 단어가 있으면 그 논리명), 논리명을 직접 고치면 그때부터 따로 갑니다.
- **저장**: 파일 › 저장(Ctrl+S) · 다른 이름으로 저장(Ctrl+Shift+S). 저장은 임시 파일에 다 쓴 뒤 바꿔 넣으므로, 저장 중에 꺼져도 원래 파일이 깨지지 않습니다.
- **고쳐서 열기**: 망가진 파일은 고칠 수 있는 데까지 고쳐서 열고, 무엇을 고쳤는지 창과 문제 목록에 보입니다. "확인 필요" 항목은 위에 노랗게 표시됩니다.
- **자동 백업**: 저장하지 않은 변경이 있으면 정해진 간격(기본 5분)마다 설정 폴더의 `backup` 폴더에 파일마다 최근 10개를 남깁니다. Relio가 비정상으로 꺼졌다면 다음에 시작할 때 복구할지 묻습니다.
- **최근 파일**: 파일 › 최근 파일에 파일 이름과 폴더가 보입니다. 맨 아래 "목록 지우기"로 비울 수 있습니다.
- **껐다 켜면**: 끌 때 열려 있던 파일을 같은 탭 순서로 다시 열고, 보던 탭을 앞에 둡니다. 그사이 없어진 파일은 건너뛰고, 하나도 없으면 시작 화면이 나옵니다. 원하지 않으면 도구 › 환경 설정 › 일반에서 "시작할 때 마지막에 열려 있던 문서 다시 열기"를 끕니다.
- **시작 화면 다시 보기**: 파일을 연 채로 보기 › 시작 화면을 고르면 새로 만들기·열기·샘플·최근 파일이 있는 시작 화면이 나옵니다. 열린 문서는 닫히지 않고, 탭을 누르거나 Esc로 돌아갑니다.

## 화면 구성

- **메뉴**: 파일 · 편집 · 보기 · 배치 · 모델 · 도구 · 도움말.
- **도구 모음**: 저장·되돌리기·확대 같은 자주 쓰는 동작.
- **팔레트**(왼쪽): 선택, 테이블, 뷰, 1:N 관계, 기존 컬럼을 사용한 관계, N:M 관계, 재귀 관계, 노트, 노트 연결, 카테고리, 이미지 삽입.
- **캔버스**: 다이어그램을 그리는 곳. Space를 누른 채 끌면 화면이 움직이고, Ctrl+마우스 휠로 확대·축소합니다.
- **아웃라인**(오른쪽): 그룹 컬럼·단어 사전·테이블·뷰·트리거·시퀀스·인덱스·테이블스페이스 목록. 이름으로 찾고, 더블클릭하면 정보 창이 열립니다. 단어·그룹을 캔버스의 테이블에 끌어다 놓으면 컬럼이 됩니다.
- **문제 목록**(아래): 설계 검사 지적(오류·경고·참고)과 파일을 고친 내역, DDL 내보내기 경고. 항목을 누르면 그 객체로 가서 잠깐 강조하고, 두 번 누르면 정보 창이 열립니다. 상태 표시줄의 "문제: 오류 n · 경고 n"을 눌러도 열립니다(보기 › 패널 › 문제 목록으로도).
- **문서 탭**(위): 열린 파일마다 탭 하나. 탭을 끌어 순서를 바꿉니다. 탭을 오른쪽 클릭하면 닫기 · 다른 탭 닫기 · 모두 닫기 · 경로 복사 · 폴더에서 열기가 있습니다. 가운데 버튼으로 누르면 닫힙니다.
- **카테고리 탭**(아래): "전체"와 카테고리마다 탭. 카테고리 탭은 그 카테고리에 속한 객체만 보여 줍니다(모델 › 카테고리 › 참조하는 테이블 보기를 켜면 참조하는 테이블도 흐리게).
- **패널 접기**: 문서 탭 줄 오른쪽 끝의 두 단추(또는 Ctrl+Alt+B · Ctrl+J, 보기 › 패널)로 오른쪽 패널(아웃라인·축소 미리보기)과 아래 패널(문제 목록)을 따로 접고 폅니다. 문서 탭을 더블클릭하면 두 패널을 한 번에 접어 캔버스를 넓게 보고, 다시 더블클릭하면 접기 전 상태로 돌아갑니다. 접은 상태는 다음에 켜도 그대로입니다.
- **상태 표시줄**: 대상 DB와 버전(누르면 바꾸는 창), 테이블·컬럼·관계 수, 배율.

## 그리기·편집

- **테이블·뷰·노트**: 팔레트에서 고르고(T · W · N) 캔버스를 클릭합니다. 더블클릭 또는 Enter로 정보 창, F2로 이름 바로 고치기.
- **관계**: 1:N 관계(R)로 부모 테이블에서 자식 테이블로 끌어 놓거나, 부모 테이블을 누른 뒤 자식 테이블을 누르면 부모 기본 키를 따라 FK 컬럼이 생깁니다(빈 곳·Esc는 취소). 이미 있는 컬럼을 쓰려면 "기존 컬럼을 사용한 관계". N:M 관계는 두 테이블을 고르면 교차 테이블을 만듭니다. 재귀 관계는 한 테이블을 고릅니다.
- **카테고리**: 카테고리 도구(C)로 끌어서 영역을 만듭니다. 영역 안에 놓인 객체가 그 카테고리에 속합니다.
- **고르기·옮기기**: 클릭, Shift+클릭으로 더하기, 빈 곳을 끌어 여러 개 고르기. 방향키로 1칸, Shift+방향키로 10칸 옮깁니다. 연결선을 끌어 꺾임점을 만들고, 배치 › 직각 연결선 · 기본값 복원.
- **테이블 크기**: 테이블·뷰를 고르면 왼쪽·오른쪽 손잡이로 너비를 바꿉니다. 넓히기는 마음대로, 줄이기는 내용이 다 보이는 너비까지입니다. 높이는 늘 컬럼 수에 맞습니다. 컬럼이 없는 테이블에는 "더블클릭해 컬럼 추가"가 흐리게 보입니다.
- **배치 메뉴**: 맞춤(왼쪽·가운데·오른쪽·위·아래), 너비·높이 맞춤, 가로·세로 정렬, 크기 자동 조정, 배경색, 글꼴.
- **복사·붙여넣기**: 객체를 다른 문서에도 붙일 수 있습니다. 컬럼을 고르고 복사하면 다른 테이블에 컬럼으로 붙습니다.
- **되돌리기**: 모든 편집은 Ctrl+Z로 되돌리고 Ctrl+Y로 다시 합니다.
- **찾기·바꾸기**: Ctrl+F는 캔버스 위 찾기 막대(아래 "찾기·강조"), Ctrl+H는 찾기·바꾸기 창입니다. 찾기·바꾸기 창은 이름·주석·형식 등에서 찾고 한꺼번에 바꿉니다. 편집 › 모든 속성 편집으로 여러 테이블의 컬럼 속성을 표에서 고칩니다.
- **보기 메뉴**: 뷰 모드(논리명·물리명·둘 다), 표기법(IE·IDEF1X), 표기 수준, 디자인, 대문자로 표시, 스탬프, 곡선 연결선, 격자. 이 설정은 문서에 저장되고 되돌릴 수 있습니다.

## 정보 창

- **테이블 정보**: 이름·주석, 컬럼(추가·삭제·순서·기본 키·NOT NULL·고유·자동 증가·기본값), 인덱스, 복합 고유 키, 고급(테이블스페이스·스키마·DB별 옵션). 컬럼은 단어 사전의 단어를 함께 쓰므로, 한 곳에서 이름을 바꾸면 같은 단어를 쓰는 모든 컬럼이 바뀝니다.
- **관계 정보**: 이름, 참조 대상(기본 키 또는 고유 키), 갱신·삭제 동작, 부모·자식 다중성. 관계를 지울 때 FK 컬럼을 함께 지울지 묻습니다.
- **노트 연결선**: 더블클릭하면 선 색을 바꾸는 연결 정보 창이 열립니다.
- **모델 메뉴**: 카테고리 관리, 그룹 관리(여러 테이블이 함께 쓰는 컬럼 묶음), 단어 사전, 변경 내역(그 시점 데이터 보기·되돌리기), 번역 관리, 테스트 데이터, 옵션(DDL·검사 설정), 모델 특성(작성자·버전 등 스탬프 내용).
- **시퀀스·트리거·테이블스페이스·인덱스**: 아웃라인에서 오른쪽 클릭으로 추가하고 더블클릭으로 고칩니다.

## 찾기·강조

- **찾기 막대**(Ctrl+F): 캔버스 위에 막대가 열리고, 테이블·컬럼·관계·노트 이름(물리명·논리명)을 치는 대로 결과를 모두 강조하고 나머지는 흐리게 합니다. 한글 초성("ㅅㅇㅈ" → 사용자)으로도 찾습니다. 설명까지 찾으려면 막대의 옵션을 켭니다.
- **결과 사이 이동**: Enter·F3은 다음, Shift+Enter·Shift+F3은 이전 결과로 가며 그 결과가 한 번 깜빡입니다. 한글을 조합하는 중에 누른 Enter는 이동하지 않습니다. Esc로 막대를 닫으면 강조가 사라집니다. 원래의 찾기·바꾸기 창은 Ctrl+H 또는 막대의 단추로 엽니다.
- **연결 강조**: 테이블·관계선·컬럼에 마우스를 올리면 연결된 선과 테이블, 대응하는 PK·FK 컬럼이 조금 진하게 보입니다(나머지는 그대로). 클릭해 고르면 연결된 것만 선명하고 나머지는 흐려집니다. 카테고리 영역을 고르면 테두리 선택 표시만 나옵니다. 테이블·컬럼에 마우스를 잠시 올리면 형식·NOT NULL·FK 대상·설명이 도구 설명으로 나옵니다.
- **설정**: 도구 › 환경 설정 › 일반 › 강조에서 마우스 올림·선택 연결 강조와 찾을 때·선택할 때 흐리게를 끄고, 흐림 정도(약하게·보통·강하게)와 깜빡임 횟수·길이를 고릅니다. **움직임 줄이기**를 켜면(기본: 시스템 설정 따름) 깜빡이지 않고 굵은 테두리로만 보입니다. 움직임은 늘 3초 안에 끝납니다.
- 강조는 화면에만 있고 이미지·HTML 내보내기와 인쇄에는 들어가지 않습니다.

## 설계 검사·추천

- **설계 검사**: 편집할 때마다 모델을 검사해 캔버스 테이블 머리에 표시(오류 ●·경고 ▲)를, 컬럼 줄에 물결 밑줄을 그립니다. 마우스를 올리면 내용이 보입니다. 참고(i)는 기본으로 문제 목록에만 있고, 보기 › 참고도 캔버스에 표시로 캔버스에도 그립니다. 표시 전체는 보기 › 설계 검사 표시로 끄고 켭니다. 상태 표시줄의 "문제" 단추는 오류·경고 수만 세고, 없으면 숨습니다. 오류는 DDL을 실행하면 실패할 문제, 경고는 고치는 게 좋은 문제, 참고는 알아 두면 좋은 것입니다. 어느 것도 저장·내보내기를 막지 않습니다.
- **검사 규칙**: 기본 키 없음, FK에 인덱스 없음, 이름이 같은 컬럼끼리 형식이 다름, 예약어 이름(테이블·컬럼·인덱스·시퀀스·트리거), 물리명 비어 있음, 형식 비어 있음, 같은 이름 테이블, 물리명에 한글·공백 등, 그리고 컬럼 없음·중복 이름 같은 기존 검사.
- **문제 목록**: 심각도별로 켜고 끄고, 이름으로 거르고, 규칙별로 묶습니다. 항목의 **고치기** 단추(예: FK 인덱스 만들기, 형식 맞추기)나 규칙 머리의 **모두 고치기**로 한 번에 고치며, 되돌리기 한 번으로 돌아갑니다. Ctrl·Shift로 여러 줄을 고르고 오른쪽 클릭하면 고치기·예외·Markdown/CSV 복사가 있습니다. 참고 지적은 규칙마다 한 줄로 접혀 있고 누르면 펼쳐집니다. 캔버스에서 객체를 오른쪽 클릭하면 메뉴 맨 아래 "지적 (n) ▸"에서도 고칠 수 있습니다.
- **F8 / Shift+F8**: 다음·이전 지적으로 갑니다.
- **예외**: "여기서 예외로"는 그 지적을 숨기고, "이 파일에서 '…' 끄기"는 그 규칙을 이 파일에서 끕니다. 예외는 이 PC의 앱 설정에 파일별로 기록되며 `.erm`은 바뀌지 않습니다(문서가 "변경됨"이 되지 않음). 문제 목록의 "예외 보기"에서 다시 풉니다.
- **환경 설정 › 설계 검사**: 규칙마다 켜고 끄기·심각도 바꾸기, 캔버스 표시·입력 중 추천·관계 이름 짝 끄기.
- **입력하는 자리에서 알림**: 테이블·컬럼 정보 창은 칸 아래 한 줄로 물리명 비어 있음·같은 이름 테이블·한글·공백·예약어·형식 비어 있음을 알려 줍니다(막지 않음). 새 컬럼 창은 아직 손대지 않은 칸의 알림을 미뤘다가 그 칸에 치거나 한 번 지나간 뒤에 보입니다. DDL 창은 "DDL 실행을 실패하게 하는 오류가 n개 있습니다"를 보여 줍니다.
- **입력 중 추천**: 컬럼 정보 창에서 물리명·논리명을 치면 단어 사전과 다른 테이블의 컬럼에서 후보가 나옵니다. 목록은 칸 위에 열려 아래 칸을 가리지 않습니다. ↓/↑로 고르고 Enter·Tab으로 받으면 이름·형식·길이·논리명이 한 번에 채워집니다(↓로 고르지 않은 Enter는 받지 않음 — 마우스를 올린 줄도 고른 것이 아님, 줄을 누르면 받음). 잘못 받았으면 "채우기 취소"를 누릅니다.
- **관계 이름 짝**: 1:N 관계 도구로 부모 테이블을 누르면 이름이 맞는 컬럼이 있는 자식 후보가 강조됩니다. 관계를 만든 뒤 같은 이름 컬럼이 둘이 되면 알림 띠의 단추로 기존 컬럼을 외래 키로 쓰도록 한 번에 바꿉니다.

## 합치기(3방향 병합)

같은 `.erm`을 두 곳에서 고쳤을 때 줄 단위가 아니라 모델 단위(테이블·컬럼·관계·필드)로 합칩니다. 양쪽이 각자 테이블을 더한 것은 충돌 없이 합치고, 같은 칸을 다르게 고친 것만 고르면 됩니다. 결과는 늘 올바른 `.erm`입니다.

- **바깥에서 파일이 바뀌었을 때**: 저장 직전 확인 창이나 창으로 돌아올 때의 바깥 변경 알림에서 **[합치기…]**를 누르면 내 변경과 바깥 변경을 합치는 합치기 탭이 열립니다.
- **Git 병합 충돌 풀기**: 파일 › 비교·병합 › Git 병합 충돌 풀기…. 충돌 표시(`<<<<<<<`)가 남은 `.erm`을 열어도 안내 창에서 바로 풀 수 있습니다. 충돌 상태인 파일을 열면 위에 알림 띠가 나옵니다.
- **다른 브랜치와 합치기**: 파일 › 비교·병합 › 다른 브랜치 버전과 합치기…에서 브랜치를 고릅니다. 줄 단위로 병합된 흔적이 있는 파일은 알림 띠의 "병합을 모델 단위로 다시 하기"로 다시 합칠 수 있습니다.
- **합치기 탭**: 목록은 충돌·확인 필요·자동(내 쪽만·바깥 쪽만·양쪽 같음)으로 나뉩니다. 항목을 펼치면 필드마다 바탕·내 쪽·바깥 쪽 값이 보이고 줄마다 고를 수 있습니다. 캔버스는 결과·내 쪽·바깥 쪽 미리보기를 바꿔 보며 충돌한 객체를 강조합니다. 키: ↑↓ 이동, 1 내 쪽 · 2 바깥 쪽 · 3 둘 다, F8 / Shift+F8 다음·이전 충돌, Ctrl+Enter 적용.
- **적용**: 남은 충돌이 0이면 [적용]으로 문서에 넣습니다. 합친 결과 전체가 되돌리기(Ctrl+Z) 한 번으로 돌아갑니다. Git 충돌을 푼 뒤 저장하면 상태 표시줄에 `git add` 안내가 나옵니다 — Relio는 Git 저장소에 아무것도 쓰지 않습니다.
- 명령줄 `relio merge`를 Git merge driver로 등록하면 `git merge` 때 자동으로 모델 단위로 합칩니다(아래 "명령줄").

## DDL

- 파일 › 내보내기 › DDL. 대상 DB와 버전을 고르면 미리보기가 바로 바뀝니다. 지원 DB: PostgreSQL · MySQL · MariaDB · Oracle · SQL Server · DB2 · H2 · HSQLDB · SQLite · Informix · MS Access · 표준 SQL.
- 만들 것(삭제 문장, 테이블, 인덱스, FK, 시퀀스, 트리거, 뷰, 주석 등), 환경, 인코딩, 줄바꿈을 고릅니다. 설정은 문서에 저장되어 다음에도 쓰입니다.
- 그 DB 버전에서 쓸 수 없는 문법은 빼거나 바꾸고 경고로 알립니다. 경고는 문제 목록에도 남습니다.
- 처음 실행하는 DB에서는 삭제 문장이 "없음" 오류를 낼 수 있습니다. 존재 검사 문법이 있는 DB는 그것을 쓰고, 없는 DB는 맨 위에 안내 주석을 넣습니다.

## 내보내기

- 파일 › 내보내기에서 종류를 고릅니다. 고른 설정은 문서에 저장됩니다. 파일을 만들면 창 오른쪽 아래에 알림이 잠깐 뜨고, "폴더 열기"를 누르면 탐색기에서 그 파일을 고른 채 폴더가 열립니다(다른 이름으로 저장·익명화 사본 저장도 같습니다).
- **Excel**: 내장 템플릿 4종(한국어 테이블 정의서·영어·일본어·중국어)과 사용자 템플릿(`.xlsx`·ERMaster `.xls`). 출력은 `.xlsx`입니다. 사용자 템플릿은 도구 › 환경 설정 › Excel 템플릿에 등록하고, 내장 템플릿을 파일로 저장해 고쳐 쓸 수 있습니다.
- **HTML**: 인터넷 없이 보는 정적 문서(그림·테이블·컬럼·인덱스).
- **이미지**: PNG · JPG · BMP · SVG, 여백과 카테고리별 그림.
- **사전**: 단어 사전 CSV. **번역 사전**: 물리명·논리명 쌍 파일(DB에서 가져올 때 논리명 채우기에 씀).
- **테스트 데이터**: SQL(INSERT) · DBUnit XML. **Java**: 클래스 소스와 Hibernate 매핑, 또는 형식 "JPA Entity"(`@Entity` 클래스 — 패키지 `jakarta`/`javax`, 날짜 `java.time`/`java.util.Date`, 자식 목록 필드, 외래 키를 값 필드로).
- **인쇄**: 파일 › 페이지 설정, 파일 › 인쇄(Ctrl+P) — 미리보기에서 쪽 나눔을 보고 OS 인쇄 창으로 보냅니다.

## 다른 형식 연동

- **내보내기**: 파일 › 내보내기 › DBML · Mermaid · Markdown 문서 · 모델 JSON. 범위(전체 · 카테고리 · 캔버스에서 고른 테이블), 출력 파일, 인코딩, 줄바꿈, 형식별 옵션을 고릅니다. DBML · Mermaid · Markdown은 "클립보드로 복사"로 파일 없이 바로 붙여 넣을 수 있습니다.
- **DBML**: dbdiagram.io 등에서 쓰는 글 형식. 컬럼 그룹은 TablePartial, 노트는 스티키 노트로 씁니다.
- **Mermaid**: GitHub · 노션 등이 그림으로 보여 주는 `erDiagram`. 논리명을 별칭으로, 카테고리마다 파일 따로 만들 수 있습니다.
- **Markdown 문서**: 목차 · Mermaid 그림 · 테이블마다 컬럼 · 외래 키 · 인덱스 표가 있는 정의서. 표만 내보내거나 카테고리별로 묶을 수 있습니다.
- **모델 JSON**: 모델 전체를 JSON으로(구조를 설명하는 JSON Schema 포함 — 명령줄 `--print-schema`). 다른 도구와 연결할 때 씁니다.
- 이 내보내기들의 마지막 설정은 이 컴퓨터의 앱 설정에 파일별로 기억합니다. 문서(`.erm`)는 바뀌지 않으므로 내보내도 "변경됨"이 되지 않습니다.
- **가져오기**: 파일 › 가져오기 › SQL·DBML·Mermaid·Markdown에서. 파일을 고르거나 글을 붙여 넣고, 형식(자동 판별 · SQL · DBML · Mermaid · Markdown)과 SQL 방언(PostgreSQL · MySQL/MariaDB · Oracle · SQL Server · 표준 SQL — 자동 판별)을 고릅니다. `pg_dump`·`mysqldump`·SSMS 스크립트·Oracle DDL처럼 `CREATE TABLE`이 든 파일을 그대로 읽습니다.
- **가져올 곳**: 새 문서(이름 없는 새 탭) 또는 현재 문서에 합치기. 합칠 때 이름이 같은 테이블이 있으면 덮어쓰기 · 건너뛰기 · 이름 바꿔 추가를 고릅니다. 합치기 전체가 되돌리기 한 번입니다.
- **미리 보기**: 문서에 넣기 전에 찾은 테이블 · 컬럼 · 관계 · 인덱스 수와 경고를 봅니다. 가져온 뒤에는 결과 창에 경고(줄 · 열 · 내용 · 건너뛴 글)가 나오고 "목록 복사"로 복사할 수 있으며, 문제 목록에도 남습니다.
- `.sql` · `.ddl` · `.dbml` · `.mmd` · `.md` 파일을 창에 끌어다 놓으면 그 파일로 가져오기 창이 열립니다(바로 넣지 않음).
- 안전: 파일 32MB · 붙여넣기 8MB까지, 인코딩은 추측하지 않습니다(BOM 없는 UTF-8이 아닌 파일은 인코딩을 고르라고 묻습니다). 읽을 수 없는 문장은 건너뛰고 경고로 알립니다.

## DB 연동

- **가져오기**: 파일 › 가져오기 › DB에서 — 접속 → 스키마 고르기 → 객체 고르기 → 문서에 넣기. 같은 이름이 있으면 건너뛰기·이름 바꾸기·덮어쓰기를 고릅니다. 번역 사전으로 논리명을 채울 수 있습니다. 가져오기 전체가 되돌리기 한 번입니다.
- **DB로 내보내기**: 파일 › 내보내기 › DB로 내보내기 — 실행할 SQL을 먼저 보여 주고, 지원하는 DB는 한 트랜잭션으로 실행해 중간에 실패하면 되돌립니다.
- **다른 파일에서 가져오기**: 파일 › 가져오기 › 파일에서 — 다른 `.erm`의 객체를 골라 넣습니다.
- **바로 접속**: PostgreSQL · MySQL · MariaDB · SQL Server · SQLite는 앱에 드라이버가 들어 있어 따로 설치할 것이 없습니다.
- **Oracle**: Oracle 웹사이트에서 Oracle Instant Client(Basic 또는 Basic Light)를 내려받아 압축을 풀고, 그 폴더(`oci.dll`이 있는 폴더)를 도구 › 환경 설정 › DB 연결의 "Oracle Instant Client 폴더"에 등록합니다. 등록하지 않으면 PATH에서 찾습니다.
- **DB2 · Informix · MS Access**: 그 DB의 ODBC 드라이버를 설치하고 접속 창에서 DSN이나 드라이버 이름(ODBC 데이터 원본 관리자에 보이는 이름)을 지정합니다. DB마다 기본 드라이버 이름은 도구 › 환경 설정 › DB 연결에서 정합니다. 드라이버 **파일**(`.dll`)을 직접 쓰려면 그곳에 등록해야 합니다.
- **H2 · HSQLDB**: 직접 접속할 수 없습니다. DDL 파일로 내보내 실행하세요.
- **암호**: 기본으로 Windows 자격 증명 관리자에 저장합니다(`relio:`로 시작하는 항목). 저장하지 않고 접속할 때마다 묻게 할 수도 있습니다. ERMaster처럼 `.erm` 안에 저장하려면 파일별로 켭니다(파일을 남에게 주면 암호도 함께 갑니다). 저장한 암호는 도구 › 환경 설정 › 암호에서 보고 지웁니다.
- **보안**: 남에게 받은 `.erm`에 적힌 드라이버 파일, 네트워크 경로(`\\서버\…`), DSN 파일은 쓰지 않습니다. 필요한 값은 접속 창에서 직접 입력하거나 환경 설정에 등록하세요.

## 환경 설정

도구 › 환경 설정. 바꾸는 즉시 저장됩니다.

- **일반**: 표시 언어(한국어 · English · 日本語 · 中文, 비우면 OS 언어 — 일본어 · 중국어는 0.12.0까지 번역한 문구만 있고 새 문구는 영어로 나옵니다), 테마(시스템·낮·밤·벚꽃·라벤더·숲·모카·서리 — 테이블 같은 노드 색은 밝은 테마면 낮과 같이 그리고, 어두운 테마(모카·서리)는 창·메뉴·패널만 테마 색이고 캔버스는 기본 어두운 캔버스 그대로이며, 내보내기·인쇄는 늘 밝은 색. 벚꽃·라벤더·숲·모카·서리는 Windows 11에서 창 제목 줄도 테마 색), 캔버스 색(테마·낮 — 낮이면 어두운 테마에서도 캔버스를 밝게), 자동 백업 간격, 마지막 문서 다시 열기, 파일별 기록 정리, 강조(연결 강조·흐림 정도·깜빡임·움직임 줄이기).
- **글로벌 그룹**: 여러 파일이 함께 쓰는 컬럼 그룹.
- **번역 사전**: DB 가져오기에 쓸 사전 목록과 순서.
- **Excel 템플릿**: 내장 템플릿 파일로 저장, 사용자 템플릿 등록.
- **DB 연결**: 저장한 연결 이름 바꾸기·지우기, Oracle Instant Client 폴더, DB별 ODBC 드라이버.
- **설계 검사**: 규칙마다 켜고 끄기·심각도, 캔버스 표시·입력 중 추천·관계 이름 짝.
- **단축키**: 표를 보고 바꿉니다. 겹치는 키는 "겹침"으로 알립니다.
- **암호**: 보안 저장소에 있는 암호 목록과 지우기.
- 설정은 `%APPDATA%\Relio`에 있습니다. 앱을 지웠다 다시 설치해도 남습니다.

## 명령줄

같은 실행 파일(`relio`)로 화면 없이 내보내고, 가져오고, 비교하고, 합치고, 검사하고, DB와 주고받습니다. 빌드 스크립트나 CI에 넣기 좋습니다.

```
relio export ddl --input model.erm --output model.sql --db-version 17
relio export excel --input model.erm --output model.xlsx --template default_ko
relio export dbml --input model.erm --output model.dbml
relio export mermaid --input model.erm --output - --category 영업
relio export json --input model.erm --output model.json --include images,history
relio export java --input model.erm --output-dir src --style jpa
relio import auto --input schema.sql --output schema.erm
relio diff old.erm new.erm --format markdown --output diff.md --exit-code
relio merge base.erm mine.erm theirs.erm -o merged.erm --report -
relio lint model.erm --format markdown --fail-on error
relio db test --db PostgreSQL --server localhost --database app --user dev --password-env PGPASSWORD
relio db import --db MySQL --database shop --user dev --output shop.erm
```

- **내보내기 종류**: `ddl` · `image` · `html` · `excel` · `testdata` · `dictionary` · `translation` · `java` · `dbml` · `mermaid` · `markdown` · `json`. 옵션을 주지 않으면 `.erm`에 저장된 마지막 내보내기 설정을 씁니다.
- **글 형식 옵션**: `--category <이름>`(그 카테고리만), `--line-feed crlf`, Mermaid `--split-categories`(카테고리마다 `<이름>-<카테고리>.mmd`), JSON `--include images,history` · `--exclude layout` · `--timestamp` · `--print-schema`(JSON Schema 출력), Java `--style jpa`와 `--jpa-namespace javax` · `--jpa-legacy-date` · `--jpa-collections` · `--jpa-fk-as-value`.
- **출력 경로 규칙**: 이미 있는 출력 파일은 묻지 않고 덮어쓰고, 출력 폴더가 없으면 만듭니다. 출력 경로가 입력 `.erm`(또는 열린 `.erm`)과 같으면 쓰지 않고 오류로 끝납니다. `--output`을 주지 않으면 `.erm`에 저장된 경로를 쓰는데, `.erm`이 있는 폴더 안을 가리킬 때만입니다 — 폴더 밖 절대 경로 · 다른 드라이브 · 네트워크 경로 · `..`이면 `--output`으로 지정하라는 오류가 납니다(남이 준 `.erm`이 다른 파일을 덮어쓰지 못하게). 확장자가 종류와 다르면 경고하고 씁니다.
- **표준 출력**: `--output -`는 글 종류(`ddl` · `dictionary` · `translation` · `dbml` · `mermaid` · `markdown` · `json`)에서 표준 출력으로 내보냅니다.
- **`--encoding`**: UTF-8(기본) · UTF-8 BOM · UTF-16LE · UTF-16BE · EUC-KR · CP949(MS949) · Shift_JIS · GBK. 모르는 이름은 오류입니다(조용히 UTF-8로 바꾸지 않음).
- **`relio import <형식>`**: 형식은 `auto` · `ddl` · `dbml` · `mermaid` · `markdown`, `--input`은 파일 또는 `-`(표준 입력), `--output`은 새 `.erm`(이미 있으면 `--force`가 있어야 덮어씀). `--dialect`(SQL 방언) · `--db`(새 문서 DB) · `--comment auto|description|logical` · `--name-case asis|db` · `--encoding` · `--strict`(경고가 있으면 만들지 않음). 경고는 표준 오류에 `<입력>:<줄>:<열>: 경고: <내용>` 꼴로 나옵니다.
- **`relio diff`**: `relio diff A.erm B.erm`, `relio diff --rev REV 파일.erm`(Git 저장소의 그 버전 ↔ 디스크), `relio diff --rev REV1 --rev REV2 파일.erm`. `--format markdown|json|csv`, `--output`(`-`이면 표준 출력), `--include structure,docs,layout,settings`, `--lang`, `--exit-code`(차이가 있으면 4). 저장소에 아무것도 쓰지 않고 네트워크에 접속하지 않습니다. Git 비교 도구로 쓸 수 있습니다: `git difftool -x "relio diff" -- 모델.erm`.
- **`relio merge`**: `relio merge 바탕.erm 내쪽.erm 바깥쪽.erm -o 결과.erm`. 결과 파일에는 충돌 표시를 넣지 않고(늘 올바른 `.erm`), 충돌이 남으면 `--on-conflict ours|theirs`(기본 ours) 쪽 값을 넣고 종료 코드 5로 끝납니다. `--keep-numbers ours|theirs`(번호를 지킬 쪽), `--report <경로|->` · `--report-format markdown|json`(충돌·자동 항목 보고서), `--label-base` · `--label-ours` · `--label-theirs`(이름표), `--no-sort`(정렬 저장 끄기), `--lang`. `-o`는 내 쪽 입력과 같은 경로여도 됩니다. 저장소에는 아무것도 쓰지 않습니다.
- **Git merge driver**: 저장소의 `.gitattributes`에 한 줄을 넣고 Git 설정에 드라이버를 등록하면 `git merge`·`git rebase`가 `.erm`을 모델 단위로 합칩니다. 충돌이 남으면(종료 코드 5) Git은 그 파일을 충돌로 남기고, Relio에서 열어 파일 › 비교·병합 › Git 병합 충돌 풀기…로 마저 풉니다. 설치 파일은 `relio`를 PATH에 넣지 않으므로 Windows에서는 설치 폴더의 `relio.exe` 전체 경로를 `/`로 적고 따옴표로 감쌉니다(아래 첫 예). `.gitattributes`에는 `text eol=lf`도 함께 적어 커밋 안의 줄 끝을 LF로 맞춥니다 — ERMaster(CRLF)와 Relio(LF)를 섞어 쓰는 팀에서 줄 끝 차이 때문에 병합·저장마다 파일 전체가 바뀐 것으로 잡히지 않게. `--label-base %S`는 보고서의 바탕 이름표를 Git 임시 파일 이름 대신 공통 조상 이름으로 씁니다. 드라이버는 Git 설정이라 저장소에 따라가지 않으니 **ERMaster를 쓰는 팀원을 포함해 병합하는 사람 모두** 자기 PC에 등록해야 합니다(등록하지 않은 사람의 `git merge`는 줄 단위로 합쳐 충돌 표시가 남음). **주의**: 등록했지만 Git이 드라이버를 찾지 못하면(경로가 틀림 — 출력에 `relio: command not found` 같은 줄) Git은 충돌 표시 없이 **내 쪽 파일만 남긴 채** 충돌로 표시합니다. 그대로 `git add`하면 바깥 쪽 변경이 사라지니, 등록한 뒤 `git config --get merge.relio.driver`의 경로를 그대로 붙여 `"…/relio.exe" --version`이 판 번호를 내는지, `git check-attr merge -- 모델.erm`이 `merge: relio`인지 확인하세요.

```
# .gitattributes
*.erm text eol=lf merge=relio

git config merge.relio.name "Relio model merge"

# Windows (Git Bash) — 설치된 relio.exe 전체 경로
git config merge.relio.driver '"C:/Users/<사용자>/AppData/Local/Relio/relio.exe" merge %O %A %B -o %A --label-base %S --label-ours %X --label-theirs %Y'

# relio가 PATH에 있을 때
git config merge.relio.driver "relio merge %O %A %B -o %A --label-base %S --label-ours %X --label-theirs %Y"
```

- **`relio lint`**: `relio lint 모델.erm`. `--format text|markdown|json`, `--output`(기본 `-` 표준 출력), `--fail-on error|warning|info|none`(이 심각도 이상 지적이 있으면 종료 코드 6, 기본 warning), `--disable`·`--only`(쉼표로 구분한 규칙 ID — 예: `pk-missing`, `fk-no-index`, `reserved-word`), `--db-version`, `--lang`. 앱에서 예외로 한 것은 적용되지 않으므로(어느 PC에서나 같은 결과) 규칙은 `--disable`로 끕니다. `relio export ddl`도 DDL 실행을 실패하게 하는 오류가 있으면 표준 오류에 한 줄 알립니다.
- **`relio db`**: `test`(접속 시험) · `export`(DB로 내보내기) · `import`(DB에서 가져오기) · `roundtrip`(왕복 시험). 암호는 `--password-env <환경 변수>`로 넘깁니다.
- `relio --help`, `relio export <종류> --help`, `relio import --help`, `relio diff --help`, `relio merge --help`, `relio lint --help`, `relio db <명령> --help`로 옵션을 봅니다. 출력 언어는 앱 언어를 따르고, `RELIO_LANG`(ko · en · ja · zh)로 바꿀 수 있습니다.

| 종료 코드 | 뜻 |
|---|---|
| 0 | 성공(경고 포함) — `diff --exit-code`면 같음 |
| 1 | 입력·옵션 오류(가져오기: 테이블을 하나도 찾지 못함, `--strict`에서 경고) |
| 2 | 출력 쓰기 실패(가져오기: `--force` 없이 이미 있는 `.erm`) |
| 3 | 이 DB로 바꿀 수 없음 |
| 4 | 차이 있음(`db roundtrip`, `diff --exit-code`) |
| 5 | 병합 충돌이 남음(`merge`) |
| 6 | `--fail-on` 단계 이상 지적이 있음(`lint`) |

## 내 정보는 어디에 저장되나요

| 무엇 | 위치 |
|---|---|
| 모델 | 저장한 `.erm` 파일 |
| 앱 설정 · 연결 목록 · 최근 파일 · 파일별 기록(DDL 대상 버전 · 글 형식 내보내기 설정 등) | `%APPDATA%\Relio` |
| 자동 백업(파일마다 최근 10개) | `%APPDATA%\Relio\backup` |
| DB 암호 | Windows 자격 증명 관리자(`relio:`로 시작하는 항목) — 파일별로 켜면 `.erm` 안 |

Relio는 인터넷에 스스로 접속하지 않고, 사용 기록 · 오류 보고 · 파일 내용을 밖으로 보내지 않습니다.

## 설치 · 지우기

- **설치**: 설치 파일(`Relio_<버전>_x64-setup.exe`)을 실행합니다. 관리자 권한 없이 지금 사용자 계정에만 설치됩니다. 바탕화면 바로가기는 설치 중에 고릅니다. 설치 없이 쓰는 실행판(`Relio_<버전>_x64_portable.zip`)도 같은 설정 폴더를 씁니다.
- **지원**: Windows 10 · 11(64비트). 화면에 쓰는 Microsoft Edge WebView2는 Windows 10 · 11에 기본으로 들어 있습니다.
- **업데이트**: 새 설치 파일을 그대로 실행하면 덮어 설치되고 설정은 남습니다.
- **지우기**: Windows 설정 › 앱에서 Relio를 제거합니다. 설정 · 연결 목록 · 백업(`%APPDATA%\Relio`)은 남아서 다시 설치하면 그대로 씁니다.
- **흔적까지 지우기**: 제거한 뒤 `%APPDATA%\Relio` 폴더를 지우고, Windows 자격 증명 관리자에서 `relio:`로 시작하는 항목을 지웁니다(먼저 도구 › 환경 설정 › 암호에서 지워도 됩니다).

## 문제 해결

- **파일이 안 열립니다**: 오류 창에 줄·칸 위치가 나옵니다. 너무 깊게 중첩된 파일 등 비정상 구조는 안전을 위해 열지 않습니다. 고쳐서 열린 경우에는 고친 내역을 확인하세요.
- **다른 프로그램이 파일을 바꿨습니다**: 창으로 돌아오면 다시 읽을지 묻습니다. 저장하지 않은 변경이 있으면 [합치기…](내 변경과 바깥 변경을 모델 단위로 합침) · "다시 읽기(내 변경 버림)" · "내 변경 유지" 중에서 고릅니다.
- **Git 병합 뒤 파일이 안 열립니다**: 충돌 표시(`<<<<<<<`)가 남은 파일이면 안내 창에서 Git 병합 충돌 풀기로 바로 갑니다. 줄 단위 "양쪽 받기"로 망가진 파일은 어느 테이블·컬럼인지 고친 내역에 나오고, "병합을 모델 단위로 다시 하기"로 다시 합칠 수 있습니다.
- **갑자기 꺼졌습니다**: 다시 시작하면 자동 백업에서 복구할지 묻습니다. 백업은 설정 폴더의 `backup` 폴더에도 있습니다.
- **DB에 접속되지 않습니다**: 서버·포트·DB 이름·방화벽을 확인하세요. 자체 서명 인증서를 쓰는 서버는 접속 창의 "서버 인증서 신뢰"를 켭니다. Oracle은 Instant Client 폴더 등록, DB2 · Informix · MS Access는 ODBC 드라이버 설치를 확인하세요.
- **"보안상 쓰지 않습니다" 안내**: 문서에 적힌 드라이버 파일·네트워크 경로·DSN 파일을 막은 것입니다. 믿을 수 있는 값이면 환경 설정에 등록하거나 접속 창에 직접 입력하세요.
- **설치 파일 실행 때 Windows 경고**: Relio 설치 파일(`Relio_<버전>_x64-setup.exe`)은 아직 코드 서명을 하지 않아서, 처음 실행할 때 "Windows의 PC 보호" 창이 뜰 수 있습니다. 받은 곳이 맞는지 확인한 뒤 **추가 정보 → 실행**을 누르세요. 회사 PC에서 서명 없는 프로그램 실행이 막혀 있으면 사내 관리자에게 문의하세요.
- **화면 글자가 이상합니다**: 도구 › 환경 설정 › 일반에서 표시 언어를 고르세요.
- **진단 기록**: Relio는 오류·시작 시간 같은 진단 정보를 이 PC의 설정 폴더 `logs`에만 남깁니다(최근 7일, 모두 합쳐 5MB까지). 인터넷으로 보내지 않고, 파일 내용·테이블 이름·경로·사용자 이름은 들어가지 않습니다. 도움말 › 문제 보고에서 "진단 기록 폴더 열기"로 파일을 보거나 "최근 기록 복사"로 마지막 200줄을 복사해 보고에 붙이면 원인을 빨리 찾을 수 있습니다. Relio가 예기치 않게 닫혔다면 다음 실행 때 한 번 알려 줍니다. 남기고 싶지 않으면 도구 › 환경 설정 › 일반 › 진단에서 끄고, "진단 기록 지우기"로 지웁니다.
- **문제를 알리려면**: 도움말 › 문제 보고에서 버전이 채워진 보고 양식을 열거나 내용을 복사합니다. 회사 파일이 걱정되면 그 창의 "익명화 사본 저장…"으로 이름·설명을 지운 사본을 붙이세요.

## ERMaster와 다른 점

- Eclipse 없이 혼자 실행됩니다. 파일은 그대로 호환되어, Relio에서 저장한 파일을 ERMaster에서도 열 수 있습니다.
- ERMaster의 알려진 문제를 고쳐서 동작합니다. 예: 뷰나 재귀 관계가 있는 파일을 저장·다시 열기, DB별로 실행 오류가 나던 DDL 문법, 테스트 데이터 SQL의 따옴표·빈 값, MySQL 가져오기에 다른 DB 객체가 섞이던 문제, 번역 사전이 대소문자를 바꾸던 문제.
- Excel 출력은 `.xlsx`입니다(ERMaster `.xls` 템플릿은 그대로 쓸 수 있습니다).
- DB 암호는 기본으로 `.erm`이 아니라 Windows 자격 증명 관리자에 저장합니다.
- 화면은 한국어 · English이고(日本語 · 中文은 일부 — 나머지는 영어로 나옴) 테마(낮·밤과 벚꽃·라벤더·숲·모카·서리)를 고를 수 있습니다.
- Git 병합 충돌을 모델 단위로 풀고(`relio merge`는 Git merge driver로도 씀), 설계 검사·입력 중 추천·찾기 막대 강조가 있습니다.
- DBML · Mermaid · Markdown · 모델 JSON으로 내보내고, SQL(`CREATE TABLE`) · DBML · Mermaid · Markdown에서 가져올 수 있습니다.
- 사용 기록·오류 보고·파일 내용을 밖으로 보내지 않습니다. 모든 기능이 인터넷 없이 동작합니다.
