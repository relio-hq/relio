Git과 합치기 ​

두 모델 비교와 변경 SQL, Git 이력 패널, 모델 단위 합치기(3방향 병합)와 Git merge driver를 설명합니다.

저장소 준비부터 따라 하려면 빠른 시작의 Git으로 함께 쓰기·합치기를 보세요. Relio는 이 모든 기능에서 Git 저장소에 아무것도 쓰지 않습니다.

저장소 준비 ​

Git 차이를 작게 만드는 정렬 저장(기본 켬)은 파일 › 정렬해 저장에 있습니다. 저장소의 .gitattributes에는 줄 끝을 맞추는 한 줄을 넣어 두세요.

*.erm text eol=lf merge=relio

비교 화면 ​

비교는 읽기 전용 탭으로 열립니다. 테이블·컬럼·관계를 이름과 번호로 짝지어, 이름이 바뀐 것은 유사도로 추정합니다.

  • 변경 목록 — 추가됨 · 삭제됨 · 변경됨 · 이름 변경 · 이동 · 속성 변경을 보여 줍니다. 항목을 펼치면 필드마다 전 · 후 값이 보입니다. 추정으로 짝지은 항목에는 "(추정)"이 붙습니다.
  • 묶음: 테이블별 / 종류별 — 변경 목록을 테이블마다 또는 변경 종류마다 묶습니다(Ctrl+Shift+G). Markdown 내보내기·복사도 이 방식을 따릅니다.
  • 필터 — 구조 · 문서 · 배치 · 설정으로 볼 변경을 고르고, 이름 검색, 추정만(이름 변경을 유사도로 추정한 항목만)으로 거릅니다.
  • 캔버스에 보일 쪽 — A 보기 · B 보기. 나머지 흐리게를 켜면 바뀌지 않은 것을 흐리게 그립니다.
  • A⇄B 바꾸기로 방향을 바꾸고, 다시 비교로 양쪽을 다시 읽습니다.
  • A 열기 · B 열기 — 고치려면 원래 파일을 엽니다.
  • 내보내기 ▾ — Markdown… · CSV… · JSON…(필터와 관계없이 전부) · 복사(Markdown) · 변경 SQL 만들기…. Markdown·CSV는 지금 필터를 따릅니다.
  • 두 모델이 같으면 "두 모델은 같습니다"가 나옵니다.

캔버스의 변경 표시 ​

  • 바뀐 노드는 테두리 색과 왼쪽 위 동그라미(+ 추가 · − 삭제 · ~ 변경)로, 바뀐 컬럼은 그 줄의 바탕색과 줄 끝 기호로 표시합니다.
  • B 보기에서 삭제된 테이블·뷰·노트·이미지는 A에 있던 자리에 회색 점선 상자(− 이름, 취소선)로, 삭제된 컬럼은 그 테이블 아래 점선 줄(− 컬럼명, 취소선)로 보입니다.
  • A 보기에서는 반대로, B에 더해진 것이 점선 상자·점선 줄(+ 이름)로 보입니다.
  • 점선 상자나 줄을 누르면 변경 목록에서 그 항목을 고릅니다.

변경 SQL 만들기 ​

비교 화면의 내보내기 ▾ › **변경 SQL 만들기…**는 A 구조의 DB를 B 구조로 바꾸는 SQL(ALTER 등)을 만듭니다. PostgreSQL · MySQL · MariaDB · SQL Server · Oracle을 지원합니다. Relio는 이 SQL을 만들기만 하고 실행하지 않습니다.

칸설명
대상 DB · 대상 제품 · 대상 버전SQL을 만들 DB.
방향 바꾸기A와 B를 바꿔 반대 방향 SQL을 만듭니다.
이름 변경으로 추정한 항목확실하지 않은 이름 변경을 어떻게 쓸지: 주석으로 남김(기본) · 이름 변경으로 · 삭제+추가로
DB 주석 반영주석 변경도 SQL로 만듭니다.
한 트랜잭션으로 감싸기스크립트 전체를 트랜잭션 하나로 감쌉니다(지원하는 DB에서).
파일 이름기본 이름 또는 Flyway 이름
  • SQL 탭에 스크립트가, 경고 탭에 위험한 변경이 보입니다. 위험한 변경은 파괴(데이터가 사라짐) · 데이터 의존(데이터에 따라 실패할 수 있음) · 호환 깨짐(바깥 프로그램이 깨질 수 있음)으로 나눠 알립니다.
  • "주석으로 남김"을 고르면 확실하지 않은 자리를 주석으로 쓰고 "확인 필요 n곳 — 고르기 전에는 결과가 B와 다릅니다"를 알립니다.
  • 만들 수 없는 변경은 스크립트 끝 "수동 처리 필요" 목록으로 알려 줍니다.
  • 저장… · 복사로 내보냅니다. 명령줄은 relio diff --format sql입니다.

주의

변경 SQL은 실행 전에 꼭 읽어 보고, "수동 처리 필요" 목록을 처리한 뒤 DB 도구에서 직접 실행하세요. 운영 DB라면 백업부터 하세요.

Git 이력 ​

파일 › Git 이력(또는 상태 표시줄의 브랜치 이름)으로 오른쪽에 패널이 열립니다.

  • 맨 위 이력을 시작할 브랜치·태그에서 지금 브랜치나 다른 브랜치·태그를 고릅니다. 새로 고침으로 다시 읽습니다.
  • 최신 커밋 카드 — 바로 앞 버전과 비교한 요약(테이블 +1 · 컬럼 +2 ~3)을 보여 줍니다. 카드를 누르면 직전 버전과 비교하고, 칩을 누르면 그 종류를 펼친 채 엽니다. 병합 커밋은 첫 번째 부모와 비교합니다.
  • 커밋 목록 아래 단추:
    • 직전 버전과 비교 — A = 바로 앞 버전, B = 고른 버전.
    • 현재와 비교 — A = 고른 버전, B = 열린 문서. 줄을 두 번 눌러도 됩니다.
    • 두 버전 비교 — Ctrl을 누른 채 두 줄을 고릅니다(오래된 쪽이 A).
    • 이 버전 열기 — 그 버전을 읽기 전용 탭으로 엽니다(다른 이름으로 저장은 됩니다).
  • 파일 이름이 바뀐 이력도 따라갑니다. 저장소 밖 파일, 저장하지 않은 문서, 읽기 전용 탭에는 이력이 없다고 알려 줍니다.

합치기 ​

같은 .erm을 두 곳에서 고쳤을 때 줄 단위가 아니라 모델 단위(테이블·컬럼·관계·필드)로 합칩니다. 양쪽이 각자 더한 것은 충돌 없이 합치고, 같은 칸을 다르게 고친 것만 고르면 됩니다. 결과는 늘 올바른 .erm입니다.

여는 길 ​

  • 바깥에서 파일이 바뀌었을 때 — 창으로 돌아올 때의 알림이나 저장 직전 확인 창에서 합치기…
  • Git 병합 충돌 — 파일 › 비교·병합 ▸ › Git 병합 충돌 풀기…. 충돌 표시(<<<<<<<)가 남은 파일을 열려고 해도 안내 창에서 바로 풉니다. 충돌 상태인 파일을 열면 위에 "Git 병합 충돌이 남아 있습니다" 띠와 풀기 단추가 나옵니다.
  • 다른 브랜치와 — 파일 › 비교·병합 ▸ › 다른 브랜치 버전과 합치기…에서 합칠 버전을 고릅니다. 저장소는 바뀌지 않고 열린 문서만 바뀝니다.
  • 줄 단위로 망가진 파일 — "이 파일은 줄 단위 병합으로 망가졌을 수 있습니다" 띠의 병합을 모델 단위로 다시 하기.

합치기 탭 ​

  • 목록은 충돌 · 확인 필요 · 자동(자동 — 내 쪽만 · 자동 — 바깥 쪽만 · 자동 — 양쪽 같음)으로 나뉩니다. 위에 자동 n · 충돌 n(남음 n) · 확인 n이 보입니다.
  • 항목을 펼치면 필드마다 바탕 · 내 쪽 · 바깥 쪽 값이 보이고 줄마다 고릅니다.
  • 캔버스에 보일 쪽 — 결과 · 내 쪽 · 바깥 쪽. 충돌한 객체를 강조하고, 나머지 흐리게로 관계없는 것을 흐립니다.
  • 이름 검색, 충돌만으로 거르고, 남은 충돌 모두 내 것 · 남은 충돌 모두 바깥 것으로 한 번에 고릅니다. 목록 복사로 항목 목록을 Markdown으로 복사합니다.
  • 문서나 디스크 파일이 그사이 또 바뀌면 알리고 다시 합치기를 권합니다.

적용 ​

남은 충돌이 0이면 적용으로 문서에 넣습니다. 합친 결과 전체가 되돌리기(Ctrl+Z) 한 번으로 돌아갑니다. 파일에 쓰려면 저장합니다. 취소는 합치지 않고 탭을 닫습니다(문서는 그대로).

Git 충돌을 푼 뒤 저장하면 상태 표시줄에 "충돌을 풀었습니다 — Git에 알리려면 git add …을(를) 실행하세요"가 나옵니다. git add는 직접 실행합니다.

Git merge driver ​

명령줄 relio merge를 Git merge driver로 등록하면 git merge·git rebase가 .erm을 자동으로 모델 단위로 합칩니다. 충돌이 남으면 Git은 그 파일을 충돌로 남기고, Relio에서 열어 Git 병합 충돌 풀기…로 마저 풉니다. 등록 방법과 확인 방법은 명령줄 › Git merge driver에 있습니다.
