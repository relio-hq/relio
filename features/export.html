내보내기 ​

Excel·HTML·이미지·사전·번역 사전·테스트 데이터·Java와 DBML·Mermaid·Markdown·모델 JSON 내보내기, 그리고 페이지 설정·인쇄를 설명합니다. DDL은 DDL 쪽에 따로 있습니다.

짧은 소개는 빠른 시작의 DDL 만들기·내보내기에 있습니다.

내보내기 메뉴 ​

파일 › 내보내기 ▸(캔버스 오른쪽 클릭 › 문서 ▸ › 내보내기 ▸도 같음)에서 고릅니다.

항목만드는 것
DDL…DB에 실행할 SQL — DDL
Excel…테이블 정의서(.xlsx)
HTML…인터넷 없이 보는 정적 문서 묶음
이미지…PNG · JPG · BMP · SVG 그림
사전…단어 사전 CSV
번역 사전…물리명·논리명 쌍 파일
테스트 데이터…INSERT SQL · DBUnit 파일
Java…Java 클래스 소스(일반 Java · JPA Entity)
DBML… · Mermaid… · Markdown 문서… · 모델 JSON…다른 도구와 주고받는 글 형식

공통으로:

  • 이미 있는 파일에 쓰면 덮어쓸지 묻습니다.
  • 파일을 만들면 앱 창 오른쪽 아래에 알림이 뜨고, 폴더 열기를 누르면 탐색기에서 그 파일을 고른 채 폴더가 열립니다.
  • 문서에 적힌 출력 경로가 문서 폴더 밖을 가리키면 "파일에 저장된 경로가 문서 폴더 밖입니다"라고 알립니다. 남에게 받은 파일이면 경로가 맞는지 확인하세요.
  • 경고가 있으면 개수를 알리고 문제 목록에 남깁니다. 오래 걸리는 내보내기는 진행 창의 취소로 멈출 수 있습니다.

Excel ​

  • 템플릿 — 내장(한국어 — 테이블 정의서 (default_ko) · 영어 (default_en) · 일본어 (default_ja) · 중국어 (default_zh)), 파일(직접 고른 템플릿), 또는 환경 설정 › Excel 템플릿에 등록한 템플릿.
  • 사용자 템플릿은 words·loops 시트와 템플릿 시트가 있는 .xlsx 또는 ERMaster .xls입니다. 출력은 늘 .xlsx이고, .xls를 고르면 .xlsx로 바꿔 씁니다.
  • 카테고리 — 전체 또는 카테고리 하나.
  • 다이어그램 그림 넣기 · 논리명을 시트 이름으로.
  • 테이블·인덱스 등은 템플릿 시트를 복사해 만들고, 시트 이름은 31자 안으로 줄이며 겹치면 (1), (2)…를 붙입니다.

내장 템플릿을 고쳐 쓰려면 도구 › 환경 설정 › Excel 템플릿에서 **파일로 저장…**한 뒤 고쳐서 사용자 템플릿으로 등록합니다. 환경 설정 › Excel 템플릿

HTML ​

출력 폴더를 고르고 다이어그램 이미지 포함 · 카테고리 이미지 포함 · **저장한 뒤 열기 (index.html)**를 정합니다. 프레임 없는 정적 HTML 묶음이라 파일을 그대로 열어 볼 수 있고 인터넷에 접속하지 않습니다. 그림·테이블·컬럼·인덱스가 들어갑니다.

이미지 ​

  • 형식은 출력 파일의 확장자로 정합니다(PNG·JPG·BMP·SVG).
  • 그림을 감싸는 영역에 사방 10px 여백, 배율 100%로 그립니다. 한 변이 16,384px를 넘으면 줄이고 알립니다.
  • **카테고리별 이미지도 출력 (표시 중인 카테고리)**를 켜면 카테고리마다 그림을 따로 만듭니다. 카테고리 폴더를 비우면 출력 파일 옆 categories 폴더에 둡니다.
  • 저장한 뒤 파일 열기.

찾기·선택 강조는 그림에 들어가지 않고, 어두운 테마에서도 늘 밝은 색으로 그립니다.

사전 ​

사전 내보내기 (CSV) — 단어 사전을 CSV로 냅니다. 열은 물리명, 논리명, 형식, 설명입니다. UTF-8 BOM 붙이기를 켜면 Excel에서 바로 열 때 한글이 깨지지 않습니다.

번역 사전 ​

번역 사전 내보내기 — 모델의 물리명·논리명 쌍을 번역 사전 파일(UTF-8, 한 줄에 물리명,논리명)로 냅니다. 사전 이름과 저장 위치를 정하고(확장자가 없으면 .txt), 미리보기로 몇 개가 들어가는지 봅니다. 넣지 않는 항목이 있으면 그 수와 이유를 보여 줍니다. 만든 사전은 DB에서 가져올 때 논리명을 채우는 데 씁니다.

테스트 데이터 ​

먼저 모델 › 테스트 데이터…에서 데이터를 만들어 둡니다. 모델 메뉴 › 테스트 데이터

  • 내보낼 테스트 데이터를 고릅니다.
  • 형식 — SQL (INSERT 문) · DBUnit XML · DBUnit Flat XML · DBUnit Excel (.xlsx).
  • **테스트 데이터 하나에 파일 하나 (이름.확장자)**를 켜면 데이터마다 파일을 따로 만듭니다.

작은따옴표·빈 값이 든 값도 SQL이 깨지지 않게 씁니다.

Java ​

칸설명
출력 폴더패키지 폴더는 그 아래에 만듭니다.
패키지 이름예: com.example.model. Java 규칙에 맞지 않으면 알립니다.
클래스 이름 접미사예: Entity. 비우면 붙이지 않습니다.
파일 인코딩
형식일반 Java 또는 JPA Entity(@Entity 클래스)
Hibernate 매핑 파일 출력 (.hbm.xml)일반 Java일 때만. JPA Entity 형식에서는 쓰지 않습니다.

JPA 옵션(형식이 JPA Entity일 때):

  • javax.persistence 쓰기 (끄면 jakarta.persistence)
  • 날짜를 java.util.Date로 (끄면 java.time)
  • 부모에 자식 목록 필드 넣기 (@OneToMany)
  • 외래 키를 객체 대신 값 필드로

글 형식 내보내기 (DBML·Mermaid·Markdown·모델 JSON) ​

공통 칸:

  • 범위 — 전체 · 카테고리 · 선택한 테이블(캔버스에서 먼저 선택).
  • 출력 파일 · 인코딩 · 줄바꿈을 CRLF로 쓰기 (Windows).
  • 클립보드로 복사 — 파일 없이 바로 붙여 넣습니다(DBML · Mermaid · Markdown).
  • 설정은 이 PC에 파일별로 기억합니다. 문서(.erm)는 바뀌지 않으므로 내보내도 "변경됨"이 되지 않습니다.
형식무엇형식 옵션
DBMLdbdiagram.io 등에서 쓰는 글 형식컬럼 그룹을 TablePartial로 쓰기 · 노트를 스티키 노트로 쓰기
MermaidGitHub·노션 등이 그림으로 보여 주는 erDiagram논리명을 별칭으로 쓰기 · mermaid 코드 울타리로 감싸기 · 카테고리마다 파일 따로 만들기
Markdown 문서목차·Mermaid 그림·테이블마다 컬럼·외래 키·인덱스 표가 있는 정의서Mermaid 그림 넣기 · 뷰 넣기 · 인덱스·고유 키 표 넣기 · 테이블 표만 (제목·목차·그림 없이) · 카테고리별로 묶기
모델 JSON모델 전체를 JSON으로 — 다른 도구와 연결할 때이미지 넣기 (Base64) · 변경 내역 넣기 · 배치(위치·크기·색) 빼기 · 만든 시각 넣기

모델 JSON의 구조를 설명하는 JSON Schema는 명령줄 relio export json --print-schema로 얻습니다. 명령줄

인쇄 ​

  • 파일 › 페이지 설정… — 방향(가로·세로, 기본 가로), 배율 %, 용지 크기(기본 A4), 여백 위 · 왼쪽 · 오른쪽 · 아래(cm).
  • 파일 › 인쇄…(Ctrl+P) — 인쇄 미리보기에서 지금 화면(전체 또는 카테고리)의 쪽 나눔과 쪽 수를 보고, **인쇄…**로 운영체제 인쇄 창에 보냅니다. 미리보기에서 **페이지 설정…**을 바로 열 수도 있습니다.
  • 인쇄는 페이지 설정의 배율로 그려 왼쪽에서 오른쪽, 위에서 아래 순으로 여러 쪽에 나눕니다. 격자 없이 흰 바탕입니다.
  • 캔버스에는 한 쪽 크기마다 연회색 선으로 쪽 경계가 보입니다(내보내기·인쇄에는 그리지 않음).
