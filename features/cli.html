명령줄 ​

같은 실행 파일(relio)로 화면 없이 내보내고, 가져오고, 비교하고, 합치고, 검사하고, DB와 주고받는 방법을 설명합니다. 빌드 스크립트나 CI에 넣기 좋습니다.

Git과 함께 쓰는 흐름은 빠른 시작의 Git으로 함께 쓰기·합치기에 있습니다.

시작하기 ​

  • 설치 파일은 relio를 PATH에 넣지 않습니다. Windows에서는 설치 폴더의 relio.exe를 전체 경로로 부르거나, 그 폴더를 직접 PATH에 넣습니다. 설치 없이 쓰는 실행판은 압축을 푼 폴더의 relio.exe입니다.
  • relio --help, relio export <종류> --help, relio import --help, relio diff --help, relio merge --help, relio lint --help, relio db <명령> --help로 옵션을 봅니다.
  • 출력 언어는 앱 언어를 따르고, 환경 변수 RELIO_LANG(ko · en · ja · zh)로 바꿀 수 있습니다.
relio export ddl --input model.erm --output model.sql --db-version 17
relio export excel --input model.erm --output model.xlsx --template default_ko
relio export dbml --input model.erm --output model.dbml
relio export mermaid --input model.erm --output - --category 영업
relio export json --input model.erm --output model.json --include images,history
relio export java --input model.erm --output-dir src --style jpa
relio import auto --input schema.sql --output schema.erm
relio diff old.erm new.erm --format markdown --output diff.md --exit-code
relio merge base.erm mine.erm theirs.erm -o merged.erm --report -
relio lint model.erm --format markdown --fail-on error
relio db test --db PostgreSQL --server localhost --database app --user dev --password-env PGPASSWORD
relio db import --db MySQL --database shop --user dev --output shop.erm

relio export ​

relio export <종류> --input <모델.erm> --output <출력>

  • 종류 — ddl · image · html · excel · testdata · dictionary · translation · java · dbml · mermaid · markdown · json.
  • 옵션을 주지 않으면 .erm에 저장된 마지막 내보내기 설정을 씁니다.
  • 종류마다 쓸 수 있는 옵션은 아래 "종류별 옵션" 표에 있습니다.
  • --encoding — UTF-8(기본) · UTF-8 BOM · UTF-16LE · UTF-16BE · EUC-KR · CP949(MS949) · Shift_JIS · GBK. 모르는 이름은 오류입니다(조용히 UTF-8로 바꾸지 않음).
  • 표준 출력 — --output -는 글 종류(ddl · dictionary · translation · dbml · mermaid · markdown · json)에서 표준 출력으로 냅니다.
  • relio export ddl은 설계 검사의 오류(DDL 실행을 실패하게 하는 문제)가 있으면 표준 오류에 한 줄 알립니다.

종류별 옵션 ​

모든 종류에 --input <모델.erm>이 있습니다. 켜고 끄는 옵션(--no-…)을 주지 않으면 .erm에 저장된 마지막 설정을 따릅니다.

종류출력그 밖의 옵션
ddl--output--db-product · --db-version · --environment(테이블스페이스 환경) · --category · --encoding · --line-feed · --comment on|off(DB 주석) · --inline-table-comment on|off · --inline-column-comment on|off · --comment-value description|logical|logical-description · --comment-replace-line-feed <문자열> · --no-comment-replace-line-feed · --set <항목>=true|false(삭제·생성 문장 하나씩, 여러 번) · --if-not-exists · --omit-schema · --native-types(Oracle 23 이상 boolean) · --no-sqlblanklines · --drop-tablespaces
image--output(확장자로 png·jpg·bmp·svg)--with-category · --no-with-category(카테고리별 그림) · --category-dir
html--output-dir--no-image · --no-category-image
excel--output(.xlsx)--template default_ko|default_en|default_ja|default_zh 또는 --template-file · --no-image · --logical-sheet-name · --physical-sheet-name · --category
dictionary--output(CSV)--no-bom
translation--output
testdata--output-dir--name <테스트 데이터 이름>(꼭 필요, 여러 번) · --format sql|dbunit-xml|dbunit-flat-xml|dbunit-excel · --encoding
java--output-dir--package · --suffix · --hibernate · --no-hibernate · --style plain|jpa · --jpa-namespace jakarta|javax · --jpa-legacy-date · --jpa-collections · --jpa-fk-as-value · --encoding
dbml--output--no-partials(컬럼 그룹을 펼쳐 씀) · --no-notes(노트 빼기)
mermaid--output--no-alias(논리명 별칭 빼기) · --fence(mermaid 코드 울타리) · --split-categories(카테고리마다 <이름>-<카테고리>.mmd)
markdown--output--no-diagram · --no-views · --tables-only · --by-category
json--output--include images,history · --exclude layout · --timestamp · --schema-version · --print-schema(JSON Schema를 표준 출력으로)

dbml · mermaid · markdown · json은 --category <이름>(그 카테고리만) · --encoding · --line-feed lf|crlf(기본 lf)도 씁니다.

출력 경로 규칙 ​

  • 이미 있는 출력 파일은 묻지 않고 덮어쓰고, 출력 폴더가 없으면 만듭니다.
  • 출력 경로가 입력 .erm과 같으면 쓰지 않고 오류로 끝납니다.
  • --output을 주지 않으면 .erm에 저장된 경로를 쓰는데, .erm이 있는 폴더 안을 가리킬 때만입니다. 폴더 밖 절대 경로 · 다른 드라이브 · 네트워크 경로 · ..이면 --output으로 지정하라는 오류가 납니다(남이 준 .erm이 다른 파일을 덮어쓰지 못하게).
  • 확장자가 종류와 다르면 경고하고 씁니다.

relio import ​

relio import <형식> --input <파일|-> --output <새.erm>

옵션설명
형식auto · ddl · dbml · mermaid · markdown
--input파일, 또는 -(표준 입력)
--output새 .erm. 이미 있으면 --force가 있어야 덮어씁니다.
--dialectSQL 방언
--db새 문서의 DB
--comment auto|description|logical주석을 논리명·설명 중 어디에 넣을지
--name-case asis|db따옴표 없는 이름을 그대로 둘지, DB 규칙대로 바꿀지
--encoding입력 인코딩
--strict경고가 있으면 만들지 않습니다.

경고는 표준 오류에 <입력>:<줄>:<열>: 경고: <내용> 꼴로 나옵니다. 가져오기와 다른 형식

relio diff ​

relio diff A.erm B.erm
relio diff --rev REV 파일.erm            # Git 저장소의 그 버전 ↔ 디스크
relio diff --rev REV1 --rev REV2 파일.erm
옵션설명
--format markdown|json|csv|sqlsql은 A 구조의 DB를 B로 바꾸는 변경 SQL(비교 화면의 변경 SQL 만들기와 같음)
--group-by table|kindMarkdown을 테이블별·종류별로 묶습니다(기본 table).
--output출력 파일. -이면 표준 출력
--include structure,docs,layout,settings비교할 범위
--lang출력 언어
--exit-code차이가 있으면 종료 코드 4

저장소에 아무것도 쓰지 않고 네트워크에 접속하지 않습니다. Git 비교 도구로도 쓸 수 있습니다: git difftool -x "relio diff" -- 모델.erm. Git과 합치기 › 비교 화면

relio merge ​

relio merge 바탕.erm 내쪽.erm 바깥쪽.erm -o 결과.erm

  • 결과 파일에는 충돌 표시를 넣지 않습니다(늘 올바른 .erm). 충돌이 남으면 --on-conflict ours|theirs(기본 ours) 쪽 값을 넣고 종료 코드 5로 끝납니다.
  • --keep-numbers ours|theirs — 번호를 지킬 쪽.
  • --report <경로|-> · --report-format markdown|json — 충돌·자동 항목 보고서.
  • --label-base · --label-ours · --label-theirs — 보고서의 이름표.
  • --no-sort — 정렬 저장 끄기. --lang — 출력 언어.
  • -o는 내 쪽 입력과 같은 경로여도 됩니다. 저장소에는 아무것도 쓰지 않습니다.

Git merge driver ​

저장소의 .gitattributes에 한 줄을 넣고 Git 설정에 드라이버를 등록하면 git merge·git rebase가 .erm을 모델 단위로 합칩니다. 충돌이 남으면(종료 코드 5) Git은 그 파일을 충돌로 남기고, Relio에서 열어 파일 › 비교·병합 ▸ › Git 병합 충돌 풀기…로 마저 풉니다.

# .gitattributes
*.erm text eol=lf merge=relio

git config merge.relio.name "Relio model merge"

# Windows (Git Bash) — 설치된 relio.exe 전체 경로
git config merge.relio.driver '"C:/Users/<사용자>/AppData/Local/Relio/relio.exe" merge %O %A %B -o %A --label-base %S --label-ours %X --label-theirs %Y'

# relio가 PATH에 있을 때
git config merge.relio.driver "relio merge %O %A %B -o %A --label-base %S --label-ours %X --label-theirs %Y"
  • Windows에서는 설치 폴더의 relio.exe 전체 경로를 /로 적고 따옴표로 감쌉니다.
  • .gitattributes의 text eol=lf는 커밋 안의 줄 끝을 LF로 맞춥니다. ERMaster(CRLF)와 Relio(LF)를 섞어 쓰는 팀에서 줄 끝 차이 때문에 파일 전체가 바뀐 것으로 잡히지 않게 합니다.
  • --label-base %S는 보고서의 바탕 이름표를 Git 임시 파일 이름 대신 공통 조상 이름으로 씁니다.
  • 드라이버는 Git 설정이라 저장소에 따라가지 않습니다. ERMaster를 쓰는 팀원을 포함해 병합하는 사람 모두 자기 PC에 등록해야 합니다. 등록하지 않은 사람의 git merge는 줄 단위로 합쳐 충돌 표시가 남습니다.

주의

등록했지만 Git이 드라이버를 찾지 못하면(경로가 틀림 — 출력에 relio: command not found 같은 줄) Git은 충돌 표시 없이 내 쪽 파일만 남긴 채 충돌로 표시합니다. 그대로 git add하면 바깥 쪽 변경이 사라집니다. 등록한 뒤 git config --get merge.relio.driver의 경로를 그대로 붙여 "…/relio.exe" --version이 판 번호를 내는지, git check-attr merge -- 모델.erm이 merge: relio인지 꼭 확인하세요.

relio lint ​

relio lint 모델.erm

옵션설명
--format text|markdown|json출력 형식
--output출력 파일(기본 - 표준 출력)
--fail-on error|warning|info|none이 심각도 이상 지적이 있으면 종료 코드 6(기본 warning)
--disable · --only쉼표로 구분한 규칙 ID(예: pk-missing, fk-no-index, reserved-word). 모든 규칙 ID는 설계 검사와 추천 › 검사 규칙 표에 있습니다.
--db-version검사 기준 DB 버전
--lang출력 언어

앱에서 예외로 한 것은 적용되지 않으므로(어느 PC에서나 같은 결과) 규칙은 --disable로 끕니다. 설계 검사와 추천

명령하는 일

종료 코드 ​

코드뜻
0성공(경고 포함) — diff --exit-code면 같음
1입력·옵션 오류(가져오기: 테이블을 하나도 찾지 못함, --strict에서 경고)
2출력 쓰기 실패(가져오기: --force 없이 이미 있는 .erm)
3이 DB로 바꿀 수 없음
4차이 있음(db roundtrip, diff --exit-code)
5병합 충돌이 남음(merge)
6--fail-on 단계 이상 지적이 있음(lint)

CI에서 쓰기 ​

  • 검사 — relio lint 모델.erm --fail-on error로 오류가 있으면 빌드를 실패시킵니다.
  • DDL 만들기 — relio export ddl --input 모델.erm --output 모델.sql --db-version 17.
  • 변경 확인 — relio diff --rev main 모델.erm --format markdown --output diff.md로 바뀐 내용을 문서로 남깁니다.
  • 변경 SQL — relio diff 이전.erm 이후.erm --format sql --output alter.sql.
