파일 ​

새로 만들기·열기·저장, 최근 파일, 문서 탭, 자동 백업과 복구처럼 파일 메뉴와 문서 탭에서 하는 일을 설명합니다.

처음이라면 빠른 시작의 처음 시작하기와 ERMaster에서 넘어오기를 먼저 보세요.

메뉴 › 항목단축키하는 일

파일 › 닫기Ctrl+W지금 문서 탭을 닫습니다.
파일 › 저장Ctrl+S지금 문서를 저장합니다.

새로 만들기 ​

파일 › 새 다이어그램(Ctrl+N)을 누르면 새 다이어그램 창이 열립니다.

  • 데이터베이스 — 지원 DB 12가지 가운데 하나를 고릅니다. MySQL을 고르면 대상 제품(MySQL·MariaDB)도 고릅니다.
  • 대상 버전 — 실제로 쓸 DB 버전입니다. 고르지 않으면 "버전 미지정"이 되어 그 DB의 가장 낮은 지원 버전(예: PostgreSQL 9.4)부터 되는 문법을 기준으로 설계를 검사하고 DDL을 만듭니다. 모르면 그대로 두세요.
  • 만들기를 누르면 이름 없는 새 탭이 열립니다. 위치와 이름은 처음 저장할 때 정합니다.

대상 버전은 .erm 파일 안이 아니라 이 PC에 파일마다 기억합니다. 다른 PC에서 열면 다시 고릅니다. 나중에 바꾸려면 상태 표시줄 맨 왼쪽(예: "PostgreSQL 16")을 눌러 옵션 창의 데이터베이스 탭을 엽니다.

열기 ​

  • 파일 › 열기…(Ctrl+O)로 고르거나, .erm 파일을 창에 끌어다 놓습니다. 여러 파일은 탭으로 하나씩 열립니다.
  • 이미 열려 있는 파일을 다시 열면 그 탭으로 갑니다.
  • .sql·.ddl·.dbml·.mmd·.mermaid·.md 파일을 열거나 끌어다 놓으면 바로 넣지 않고 가져오기 창이 열립니다. 가져오기는 파일 하나씩 합니다.
  • 샘플 열기 — 시작 화면이나 도움말 › 샘플 열기 ▸에서 PostgreSQL — 온라인 서점(테이블 19개)·MySQL — 회원·권한 관리(테이블 16개)를 고릅니다. 앱에 들어 있어 인터넷 없이 열리고, 이름 없는 새 문서(사본)로 열리므로 고쳐도 샘플은 그대로입니다. 저장하면 다른 이름으로 저장 창이 뜹니다.

고쳐서 열기 ​

망가진 파일은 고칠 수 있는 데까지 고쳐서 엽니다. 그때 "손상된 부분을 복구해 열었습니다" 창에 위치 · 항목 · 원래 값 · 해석한 값이 표로 나오고, 같은 내용이 문제 목록에도 남습니다. 꼭 살펴봐야 할 항목은 "확인 필요"로 위에 노랗게 표시됩니다. 목록 복사로 표를 복사할 수 있습니다. 저장하면 고친 내용으로 저장됩니다.

Git 병합 충돌 표시(<<<<<<<)가 남은 파일은 그대로 열 수 없습니다. 안내 창의 **Git 병합 충돌 풀기…**로 바로 풉니다. Git과 합치기를 보세요.

최근 파일 ​

파일 › 최근 파일 ▸에 파일 이름과 폴더가 보입니다. 앞의 아홉 개에는 번호가 붙습니다. 그사이 없어진 파일은 흐리게 보이고 열 수 없습니다. 맨 아래 목록 지우기로 목록을 비웁니다. 시작 화면의 최근 파일 목록에서는 항목마다 목록에서 빼기로 하나씩 뺄 수 있습니다.

저장 ​

  • 저장(Ctrl+S)은 바뀐 것이 있을 때 씁니다. 한 번도 저장하지 않은 새 문서·샘플 사본은 다른 이름으로 저장 창이 뜹니다.
  • 저장은 임시 파일에 다 쓴 뒤 원래 파일과 바꿔 넣습니다. 저장 중에 꺼져도 원래 파일이 깨지지 않습니다.
  • 바뀐 문서는 문서 탭 이름 앞에 *가 붙습니다.
  • 문서를 닫을 때 저장하지 않은 변경이 있으면 저장 · 저장 안 함 · 취소를 묻습니다.

저장할 때 바깥 변경을 만나면 ​

마지막으로 열거나 저장한 뒤 다른 프로그램이나 다른 사람이 파일을 바꿨으면, 저장 직전에 "저장하려는 파일이 바깥에서 바뀌었습니다" 창이 뜹니다.

단추하는 일
합치기…내 변경과 바깥 변경을 모델 단위로 합치는 합치기 탭을 엽니다.
차이 보기저장을 멈추고 바깥 파일과 내 문서를 비교 탭으로 엽니다. 다시 저장하면 또 묻습니다.
덮어쓰기 (바깥 변경 버림)바깥 변경을 버리고 내 문서로 덮어씁니다. 덮어쓰기 전 파일은 자동 백업 폴더에 남겨 둡니다.
다른 이름으로 저장…다른 파일로 저장합니다.
취소저장하지 않습니다.

파일이 지워졌거나 옮겨졌으면 "저장하려는 파일이 없어졌습니다" 창에서 이 위치에 다시 저장을 고를 수 있습니다.

창으로 돌아왔을 때 ​

열어 둔 파일을 바깥에서 바꾸면 창으로 돌아올 때 "다른 프로그램이 파일을 바꿨습니다" 창이 뜹니다. 저장하지 않은 변경이 없으면 다시 읽기 · 그대로 두기를, 있으면 합치기… · 다시 읽기 (내 변경 버림) · 내 변경 유지를 고릅니다. 열어 둔 파일이 지워졌으면 "파일이 없어졌습니다"를 알리고 문서는 그대로 둡니다. 저장하면 그 위치에 다시 만듭니다.

정렬해 저장 ​

도구 › 환경 설정 › 일반의 Git에 맞춰 정렬해 저장이 켜져 있으면(기본) 목록 순서를 고정해 저장합니다. Git 차이가 작아지고 ERMaster에서도 그대로 열립니다. 이 설정을 처음 켠 파일은 첫 저장에서 줄이 많이 바뀔 수 있으니, 파일 › 정렬해 다시 저장으로 정리만 따로 저장해 커밋해 두면 다음 변경을 검토하기 쉽습니다.

문서 탭 ​

  • 열린 파일마다 탭이 하나 생깁니다. 끌어서 순서를 바꿉니다.
  • Ctrl+Tab / Ctrl+Shift+Tab로 다음·이전 탭으로 갑니다.
  • 탭을 마우스 가운데 버튼으로 누르면 닫힙니다.
  • 탭을 오른쪽 클릭하면 닫기 · 다른 탭 닫기 · 모두 닫기 · 경로 복사 · 폴더에서 열기 · **AI 도구에서 열기…**가 있습니다. AI와 함께 쓰기
  • 탭을 더블클릭하면 오른쪽·아래 패널을 한 번에 접어 캔버스를 넓게 봅니다. 캔버스와 팔레트

껐다 켜면 ​

끌 때 열려 있던 파일을 같은 탭 순서로 다시 열고, 보던 탭을 앞에 둡니다. 그사이 없어진 파일은 건너뛰고, 하나도 없으면 시작 화면이 나옵니다. 원하지 않으면 도구 › 환경 설정 › 일반에서 시작할 때 마지막에 열려 있던 문서 다시 열기를 끕니다.

자동 백업과 복구 ​

  • 저장하지 않은 변경이 있으면 정해진 간격(기본 5분)마다 설정 폴더의 backup 폴더에 파일마다 최근 10개를 남깁니다. 간격은 도구 › 환경 설정 › 일반의 **자동 백업 간격(분)**에서 바꾸고, 0이면 끕니다.
  • Relio가 정상적으로 끝나지 않았다면 다음에 시작할 때 "저장하지 않은 문서 복구" 창이 뜹니다. 문서 · 원래 파일 · 백업 시각을 보고 고른 뒤 복구를 누릅니다. 복구하지 않음으로 넘어갈 수 있고, 백업 폴더 열기로 파일을 직접 볼 수 있습니다.
  • 복구한 문서는 "변경됨"으로 열립니다. 저장하면 원래 파일을 바꿉니다. 백업 파일은 그대로 남습니다.
