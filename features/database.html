DB 연동 ​

DB 접속 창, DB에서 가져오기, DB로 내보내기, Oracle·ODBC 준비, 암호를 저장하는 방식을 설명합니다.

따라 하는 순서는 빠른 시작의 DB에서 가져오기·DB에 반영에 있습니다.

지원하는 DB ​

DB접속 방법
PostgreSQL · MySQL · MariaDB · SQL Server · SQLite드라이버가 앱에 들어 있어 따로 설치할 것이 없습니다.
OracleOracle Instant Client를 준비합니다(아래).
DB2 · Informix · MS Access그 DB의 ODBC 드라이버를 설치합니다(아래).
H2 · HSQLDB직접 접속할 수 없습니다. DDL 파일로 내보내 실행하세요.

직접 접속할 수 없는 DB의 문서에서는 DB에서 가져오기·DB로 내보내기가 흐리게 보입니다.

접속 창 ​

DB에서 가져오기와 DB로 내보내기가 같은 접속 칸을 씁니다.

칸설명
저장된 연결저장해 둔 연결을 골라 칸을 채웁니다. 삭제로 목록에서 지웁니다.
서버 · 포트 · DB 이름접속할 곳. Oracle은 서비스명, Informix는 서버 이름(INFORMIXSERVER)도 씁니다. SQLite·MS Access는 DB 파일 경로를 고릅니다.
사용자 · 암호로그인 사용자 이름과 암호.
암호 기억 (Windows 자격 증명 관리자)암호를 Windows 자격 증명 관리자에 저장합니다.
암호를 .erm에 저장 (원본 호환 — 평문)ERMaster처럼 .erm 안에 암호를 저장합니다. 켜기 전에 확인을 받습니다.
ODBC 드라이버 · DSNDB2·Informix·MS Access일 때. 아래 "ODBC 드라이버"
Oracle 클라이언트 경로Oracle일 때. 환경 설정 › DB 연결에 등록한 폴더만 씁니다.

**고급 ▾**을 펼치면:

  • 연결 문자열 — JDBC URL, TNS 별칭·접속 설명자(Oracle), ODBC 연결 문자열(키=값;…) 등. 넣으면 서버·포트·DB 이름보다 먼저 씁니다.
  • TLS(SSL) — 서버가 지원하면 사용 · 반드시 사용 · 쓰지 않음.
  • 서버 인증서 신뢰 (자체 서명 인증서) — 자체 서명 인증서를 쓰는 서버에 접속할 때 켭니다.
  • 접속 제한 시간(초) — 1~600초, 비우면 15초.

아래 단추:

  • 연결 시험 — 접속해 보고 결과(DB 제품·버전)를 알려 줍니다.
  • 연결 이름 + 연결 목록에 저장 — 다음에 고를 수 있게 저장합니다. 암호는 연결 목록에 넣지 않습니다.

DB에서 가져오기 ​

파일 › 가져오기 ▸ › DB에서…는 접속 → 스키마 → 객체 → 확인 순서로 진행합니다. 다음으로 넘어갑니다.

  1. 접속 — 위 접속 칸을 채웁니다.
  2. 스키마 — 가져올 스키마를 고릅니다. 시스템 스키마는 기본으로 해제되어 있고, 시스템 스키마 숨기기로 목록에서 숨깁니다. 스키마 이름 찾기로 거릅니다.
  3. 객체 — 테이블 · 뷰 · 시퀀스 · 트리거를 골라 체크합니다.
  4. 확인 — 가져올 객체 수와 옵션을 확인하고 가져오기를 누릅니다.

옵션:

  • 현재 다이어그램의 정보를 삭제 — 지금 문서 내용을 지우고 DB에서 가져옵니다(확인을 받습니다, 되돌릴 수 있음).
  • 논리명을 컬럼 주석으로 사용 — 켜면 테이블·컬럼의 DB 주석을 논리명으로 읽습니다. 주석이 "논리명 : 설명" 모양이면 앞은 논리명, 뒤는 설명으로 나누고, 아니면 주석 전체를 논리명과 설명에 모두 넣습니다. 끄면 논리명을 물리명으로 채우고(번역 사전을 켜 두었으면 사전 번역을 우선) 주석은 설명에 넣습니다. 주석이 비어 있는 객체는 켜도 같은 방식으로 채웁니다.
  • 단어를 병합 — 켜면 물리명·논리명·형식·길이·소수·설명이 모두 같은 단어를 단어 사전에서 하나로 합쳐 쓰고(이미 문서에 있는 단어와도 합칩니다), 끄면 컬럼마다 단어를 따로 만듭니다.
  • 모델 DB를 …(으)로 바꾸기 — 접속한 DB와 문서의 DB가 다를 때 문서 DB를 바꿉니다.
  • 번역 사전을 켜 두었으면(모델 › 번역 관리…) 물리명으로 논리명을 채웁니다.

이름이 같은 객체가 있으면 덮어쓰기(위치·색·카테고리는 그대로 두고 내용만) · 건너뛰기 · 이름 바꿔 추가를 고릅니다. 가져오기 전체가 되돌리기(Ctrl+Z) 한 번으로 돌아갑니다.

새 문서에서 접속하거나 가져온 뒤 처음 저장하면 접속 정보도 그 파일에 기억합니다.

DB로 내보내기 ​

파일 › DB로 내보내기…(도구 모음에도 있음)는 모델을 DB에 바로 만듭니다.

  1. 접속 칸을 채웁니다.
  2. SQL 확인·실행 단계에서 실행할 SQL을 먼저 봅니다. 위에 대상 DB·버전, 지울 객체 수, "실패하면 전체 되돌림" 또는 "실패하면 일부만 반영될 수 있음"이 보입니다.
  3. 필요하면 **테이블스페이스도 만들기 (DBA 권한·서버 경로 필요)**를 켜고 SQL 다시 만들기를 누릅니다.
  4. 실행을 누르면 무엇이 지워지는지 다시 알려 주고 확인을 받습니다. DB에 없는 스키마가 있으면 CREATE SCHEMA 문장을 앞에 넣을지 묻습니다.
  • 트랜잭션 안에서 DDL을 되돌릴 수 있는 DB는 한 트랜잭션으로 실행해 중간에 실패하면 전체를 실행 전 상태로 되돌립니다. 그렇지 않은 DB는 성공한 문장까지 반영된 채 남고, 몇 번째 문장에서 실패했는지 알려 줍니다.
  • 실행 중에 취소할 수 있습니다.
  • 바뀐 것만 반영하려면 DB로 내보내기 대신 비교 화면의 변경 SQL을 씁니다. Git과 합치기 › 변경 SQL 만들기

주의

DB로 내보내기는 같은 이름의 객체를 지우고 다시 만들 수 있어 그 객체의 데이터가 사라집니다. 실행 전 확인 창의 "지워질 DB 객체" 목록을 꼭 읽고, 운영 DB라면 백업부터 하세요.

Oracle 준비 ​

  1. Oracle 웹사이트에서 Oracle Instant Client(Basic 또는 Basic Light)를 내려받아 압축을 풉니다.
  2. 그 폴더(oci.dll이 있는 폴더)를 도구 › 환경 설정 › DB 연결의 Oracle Instant Client 폴더에 등록합니다. 전체 경로여야 하고 네트워크 경로는 쓸 수 없습니다.
  3. 바꾸면 앱을 다시 시작해야 적용됩니다. 등록하지 않으면 PATH에서 찾습니다.

ODBC 드라이버 (DB2 · Informix · MS Access) ​

  1. 그 DB의 ODBC 드라이버를 설치합니다.
  2. 접속 창의 ODBC 드라이버에 설치된 드라이버 이름(ODBC 데이터 원본 관리자에 보이는 이름)을 넣거나, DSN을 고릅니다. DSN을 적으면 서버·포트·DB 대신 DSN 설정을 씁니다.
  3. DB마다 기본 드라이버 이름은 도구 › 환경 설정 › DB 연결에서 정합니다. 드라이버 파일(.dll)을 직접 쓰려면 반드시 그곳에 등록해야 합니다.

암호를 저장하는 방식 ​

  • 기본 — Windows 자격 증명 관리자에 저장합니다(relio:로 시작하는 항목).
  • 저장하지 않기 — 암호 기억을 끄면 접속할 때마다 묻습니다.
  • .erm 안에 저장 — ERMaster처럼 파일 안에 평문으로 저장합니다. 파일별로 켜며, 파일을 남에게 주면 암호도 함께 갑니다.
  • 저장한 암호는 도구 › 환경 설정 › 암호에서 보고 지웁니다. 어느 파일이 어느 방식을 쓰는지는 이 PC에 파일마다 기억합니다.

보안 ​

남에게 받은 .erm에 적힌 드라이버 파일, 네트워크 경로(\\서버\…), DSN 파일은 쓰지 않고 "보안상 쓰지 않습니다"라고 알립니다. 믿을 수 있는 값이면 환경 설정에 등록하거나 접속 창에 직접 입력하세요.
